# Хвосты: что не сделано

Единственный файл про незакрытое. Здесь только работы, которым нужен код, и
причина, по которой они ещё не сделаны. Принятые решения и объяснения «почему
так» живут в коде и в [`docs/design/`](./design) — сюда они не копируются.

Обозначения: **P1** — блокирует обещанное поведение, **P2** — заметно
пользователю, **P3** — долг без срочности, **P4** — гигиена.

---

## 1. Картинки и файлы

### Разбор 2026-10-25: решения по разделу

1. **Раскладка — опция, а не новая тема.** `FileAttachment` получает `layout`
   с двумя значениями: `'row'` — файл на строку, `'strip'` — все в одну строку
   со скроллом. Нынешняя `'tile'` остаётся.
2. **Ошибки — только у поля.** `Attachment` показывает файлы, которые лежат
   в `input.files`, и ничего не знает об ошибках. Валидатор пишет их в `field`;
   «спрятать ошибку в пользу карточки» без `takeover` самого поля нельзя —
   и не нужно. `itemProps.error` не используем.
3. **Спиннер по файлу — отложен.** Сейчас нет источника: `fetch` не сообщает
   прогресс отправки, а `Attachment.progress` — прогресс серверной задачи, не
   файла. Что появится после п. 5: проверка станет пофайловой, и карточка
   сможет показывать «идёт проверка» этого файла. Загрузку на сервер — нет.
4. **«Не грузить файл» = удалить его из списка.** Отдельного исключения не
   нужно: `input.files` — и есть то, что уйдёт на сервер, а `removeAt` уже
   единственный способ убрать. Сложность не здесь, а в накоплении выбора
   (ниже): второй заход в диалог сейчас затирает первый.
5. **Валидатор ждёт один файл.** Разбирать «массив или один» — работа не
   валидатора, а поля: движок разворачивает значение `multiple` и зовёт правила
   по одному файлу, собирая по `Issue` на плохой файл. Следствие: `image.ts`
   перестаёт ходить по `filesOf` и работает с одним `File`.
   **Следствие второе:** сумма файлов больше не дело `v.maxSize` — её считает
   сама библиотека и отдаёт общей ошибкой без пути (см. «Бюджет формы» ниже).
6. **Поток — после `lib/storage`.** Пока хранилища нет, приём остаётся
   буферным (`request.formData()`); потоковый разбор — этап `lib/storage`.
7. **`avatar_url` — не хвост.** Это колонка ссылки на картинку: сегодня
   `data:`-строка, с хранилищем — URL. Одно имя, один смысл, миграция не нужна.
8. **Стража нет.** Правило `layer-guard` для сырых байтов не написано —
   решаем, писать ли (см. последний пункт раздела).

### Бюджет формы — общая ошибка без поля — **P1**, решение

Сумма файлов против бюджета — свойство **формы**, а не поля: складывать все
файловые поля в правило одного поля значит дублировать обход в каждом правиле.
После перехода на «валидатор ждёт один файл» у `v.maxSize` не остаётся ничего,
кроме личного предела файла; сумма переезжает в библиотеку.

**Что уже есть в ядре под это (проверено по коду):**

| Механизм | Факт |
|---|---|
| ошибка без пути | `FormError.path?` необязателен: «нет пути — общая» (`result.ts:20`, `errors.ts` `Split.common`) |
| разделение | `split(shown)` → `common` и `byField`; `bind` отдаёт `state.common` |
| показ | `Common.svelte` в `#components/form` рисует общие ошибки (`ProfileForm.svelte:122`, `SeedForm.svelte:187`) |
| текст | `makeRenderer` (`messages.ts:117`): свой `template` → «поле:код» → код → **код как текст**. Словарь формы (`defineForm({ messages })`) и пакета (`DICT` в `messages.ts`) уже работают |
| блокировка | `submit.ts:244`: любая ошибка при `validate === 'full'` останавливает отправку — общая считается наравне с полевой |
| стабильность | `stableId` для ошибки без пути даёт `*:код:hash`, дубли схлопываются |

**Варианты, где проверять сумму:**

- **A. В библиотеке, отдельной ступенью `validate` (рекомендую).** `budget.ts`
  получает `budgetIssues(description, values, limits) → FormError[]` без пути,
  код `form.budget` (`params`: `max`, `total`, `files`). `validate.ts` зовёт его
  рядом с `opts.formValidator` после полевых правил. Форма ничего не объявляет:
  есть бюджет — есть проверка. Текст — из словаря по коду, нет записи → код
  показывается как текст (это уже умолчание `makeRenderer`).
- **B. Через `defineForm({ validator })`.** Каждая форма обязана помнить про
  проверку; забыл — переполнение ловит только транспорт, то есть 413 вместо
  сообщения. Ядро не гарантирует.
- **C. Вид ограничения с областью `form`.** Правило объявляет, что считается по
  форме, движок поднимает его наверх. Больше машинерии ради того же результата:
  вид ограничения нужен для показа в атрибутах и снятия действием, а бюджету
  ни то, ни другое не нужно.
- **D. Псевдополе `'*'`.** Работает за счёт `split`, но это хак: поле, которого
  нет в описании, всплывёт в `byField` и в обходе полей.

**Что меняется в коде при A:** `v.maxSize(n)` — только `min(n, бюджет файлов)`
по одному файлу; сумма и `file.budget` уходят из `validators.ts` в `budget.ts`;
сообщение `file.budget` остаётся в словаре пакета и получает `params.total`.
Тест: два файла по 4 МиБ при бюджете 7 → одна общая ошибка `form.budget`,
поле-владелец не подсвечивается.

### Раскладка `FileAttachment` — **P2**, делать

Две раскладки: `'row'` (колонка) и `'tile'` (перенос). Горизонтального ряда
со скроллом нет.

**Дальше:** `layout: 'row' | 'strip' | 'tile'`; `strip` — одна строка,
`overflow-x: auto`, карточки не сжимаются.

### Развёртывание файлов в движке — **P2**, делать

Правила `v.accept` и `v.maxSize` сами идут по `filesOf(value).find(...)`
(`validators.ts:380,395`), проверка `image` — тоже. Пока это так, каждое новое
правило обязано повторять обход, а ошибка выходит одна на поле.

**Дальше:** движок зовёт правила по одному файлу и собирает `params.name` у
каждого `Issue`. Открытый вопрос — правила счёта (`v.maxCount`, сумма бюджета):
они смотрят на весь список, а не на файл.

### Выбор из разных папок — **P2**

`FileAttachment` в `multiple` заменяет прежний выбор новым (`onchange` →
`pickedFiles = list`). Второй заход в диалог теряет первый файл.

**Дальше:** при `multiple` дополнять накопленное (дедупликация по
`name+size+lastModified`), собирать `FileList` через `DataTransfer` и класть
обратно в `input.files`, чтобы форма уносила всё выбранное.

### Приём потоком без RAM — **P1**, после `lib/storage`

Тело читается `request.formData()` целиком: файл лежит в памяти функции, на
Vercel — упирается в 4.5 МБ платформенного лимита. Решено не трогать, пока нет
хранилища: поток нужен, чтобы писать части сразу в объект, а писать некуда.

**Дальше (после `lib/storage`):** потоковый разбор multipart (текст в память,
файловые части сразу в `CreateMultipartUpload`, части по 8 МиБ), `Complete`
только после полного тела, `Abort` при обрыве; валидаторам — дескриптор
(`PreparedFile`: ключ, размер, медиатип, префикс 256 КиБ) вместо `File`.
Зависимость `@remix-run/multipart-parser` (1.1.0, MIT, 159 КиБ) — установка
владельцем не разрешена, начинать с неё.

### URL вместо base64 — **P1**, это и есть `lib/storage`

`user_profile.avatar_url` — ссылка на картинку: сегодня в ней `data:`-строка,
с хранилищем должна лежать ссылка на объект. Схема принимает оба вида,
переписывать колонку не нужно.

**Дальше:** `lib/storage` (вес, нарезка, хеш, `PreparedFile` → ключ → URL);
после него — выдача байтов отдельным кэшируемым GET-роутом и снятие base64 из
`auth_tmp`: запечатанная кука с фото весит 11–27 КБ против лимита 4 КБ.

### Страж `layer-guard`: сырые байты мимо конвейера — **P3**, не написан

Правила нет; маршрут может прочитать `.arrayBuffer()` у `File` и никто это не
поймает.

**Дальше:** правило в `tooling/layer-guard.mjs` — в `src/routes/` и
`src/content/` запрещены `file.arrayBuffer()`, `new Response(file)` и ручной
`btoa` для `data:image/`; разрешён только `#lib/image`. Бренд `PreparedFile` —
позже, вместе с потоком.

## 2. Формы

### Очередь заявок в памяти инстанса — **P2**

`src/routes/(site)/(app)/form/queue.server.ts` держит заявки в
`localStore` (TTL 24 ч). Рестарт или другой инстанс — `jobStatus(id)` пуст.

**Дальше:** `sharedStore` (`cache_kv`) с тем же TTL; заодно оживить
`outcome: 'queued'` — с JS опрос `pollUntilDone`, без JS `303` на `statusUrl`.

### Бюджет тела: остаток — **P3**

Бюджет доезжает из env до `data-budget` и `ctx.limits`. Не сверено на живом
маршруте: `limits.maxFileSize`/`maxValuesPerKey` в транспорте.

**Дальше:** прогнать форму с бюджетом, объявленным из env, и убедиться, что
`413` приходит от нас, а не от платформы.

## 3. Приложение

### `useHeadSeo` не вызывается ниоткуда — **P3**

`src/components/shell/page.svelte.ts` + реэкспорт: два вхождения, ноль вызовов.
Метаданные страниц не заполняются, подпись обещает реактивность, которой при
SSR не бывает.

**Дальше:** удалить из публичного входа `#components`; вернуть, когда появится
контент-слой с настоящими описаниями.

### `steps`: служебный шаг адресуем — **P3**

`addressable` есть только у модалок. Шаг результата или подтверждения получает
свой адрес и перезагружается по ссылке.

**Дальше:** `addressable?: boolean` в описании шагов, — когда появится первый
служебный шаг. Сейчас все адресуемы by design.

### CSP — **P3**

`kit.csp` не включён: нужны sha256 раннего скрипта, self-host шрифта и
`frame-ancestors` в dev. Разбор — [`docs/design/client-integrity.md`](./design/client-integrity.md).

## 4. Вне кода

- **Браузерные сценарии** `test/browser/*.mjs` не прогонялись: в песочнице нет
  бинарников Playwright. Прогон — на стороне владельца.
- **`#lib/db`**: ACL и generic REST (`src/lib/db/docs/ACL-DESIGN.md`), история
  ручных миграций и вычисляемые поля (`PORTING.md` §3.1) — отложены владельцем.
- **Полный прогон vitest** идёт ~2 минуты на 2 vCPU / 1,9 ГБ RAM без swap;
  в ходе работы гоняется только затронутая область, полный — перед коммитом
  крупной пачки.
