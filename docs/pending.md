# Хвосты: что не сделано

Единственный файл про незакрытое. Здесь только работы, которым нужен код, и
причина, по которой они ещё не сделаны. Принятые решения и объяснения «почему
так» живут в коде и в [`docs/design/`](./design) — сюда они не копируются.

Обозначения: **P1** — блокирует обещанное поведение, **P2** — заметно
пользователю, **P3** — долг без срочности, **P4** — гигиена.

---

## 1. Картинки и файлы

### Сделано

- **Раскладка — опция.** `FileAttachment.layout`: `'row'` (файл на строку,
  умолчание), `'tile'` (перенос), `'strip'` (одна строка, `overflow-x: auto`,
  карточки `shrink-0`, внутри — плитка). Тип `FileAttachmentLayout` = `AttachmentLayout | 'strip'`;
  сама `Attachment` про полосу не знает.
- **Накопление выбора из разных папок.** При `multiple` второй заход в диалог
  дополняет первый, а не затирает: дедупликация по `name + size + lastModified`,
  склейка кладётся обратно в `input.files` через `DataTransfer`, форма уносит всё.
  Своё событие `change` (удаление файла) не склеивается — иначе удалённый файл
  возвращался бы в список.
- **Ошибки — только у поля.** `Attachment` показывает файлы из `input.files` и
  ничего не знает об ошибках; `itemProps.error` не используется.
- **«Не грузить файл» = удалить его.** Отдельного исключения нет: `input.files` —
  и есть то, что уйдёт на сервер; `removeAt` — единственный способ убрать.
- **Валидатор ждёт один файл.** Движок сам разворачивает `multiple`
  (`runPerItem` в `validators.ts`, `perItem` у проверки в `CheckRegistry`) и зовёт
  правило по каждому файлу — на клиенте и сервере одинаково. По `Issue` на каждый
  плохой файл, с `params.name`. `image.ts` работает с одним `File`; `v.accept` и
  `v.maxSize` тоже судят один файл.
- **Сумма файлов — не дело `v.maxSize`.** Вес тела считает библиотека
  (`weight.ts`: алгоритм сериализации multipart по черновику WHATWG, UTF-8 байтами,
  граница по умолчанию 70 Б, точная — `boundaryBytesOf`), а `validateForm` отдаёт
  **общую** ошибку без пути (`form.budget`), которая блокирует отправку.
- **Спиннер по файлу — отложен осознанно.** Прогресса отправки `fetch` не даёт;
  `Attachment.progress` — прогресс серверной задачи. Пофайловая проверка появилась
  (см. выше), так что «идёт проверка этого файла» показать можно, когда будет
  источник; загрузку на сервер — нет.
- **`avatar_url` — не хвост.** Колонка ссылки на картинку: сегодня `data:`-строка,
  с хранилищем — URL. Одно имя, один смысл, миграция не нужна.
- **Страж `layer-guard` написан.** `tooling/layer-guard.mjs`: пара
  «`arrayBuffer()`/`FileReader` + `btoa`» (файл целиком в base64) запрещена в
  `src/` вне двух допущенных мест — аватар профиля и `/fields`; заголовок через
  `blob.slice(0, N)` законен. Тест — в `tooling/layer-guard.test.mjs`.

### Ждёт `lib/storage` — **P1**

Оба пункта заблокированы одним и тем же: хранилища нет, писать файлы некуда.
Поэтому они здесь, а не «сделаны», и первыми уедут в этап `lib/storage`.

**Приём потоком без RAM.** Сейчас тело читается `request.formData()` целиком:
файл лежит в памяти функции, на Vercel упирается в 4.5 МБ платформенного лимита.
Дальше: потоковый разбор multipart (текст в память, файловые части сразу в
`CreateMultipartUpload`, части по 8 МиБ), `Complete` — только после полного тела,
`Abort` — при обрыве; валидаторам — дескриптор (`PreparedFile`: ключ, размер,
медиатип, префикс 256 КиБ) вместо `File`. Начинать с `@remix-run/multipart-parser`
(1.1.0, MIT, 159 КиБ) — установку владелец пока не разрешал.

**URL вместо base64.** `user_profile.avatar_url` должна хранить ссылку на объект,
а не `data:`-строку; схема принимает оба вида, переписывать колонку не нужно.
Дальше: `lib/storage` (вес, нарезка, хеш, `PreparedFile` → ключ → URL), затем
выдача байтов отдельным кэшируемым GET-роутом и снятие base64 из `auth_tmp`:
запечатанная кука с фото весит 11–27 КБ против лимита 4 КБ.

## 2. Формы

### Очередь заявок в памяти инстанса — **P2**

`src/routes/(site)/(app)/form/queue.server.ts` держит заявки в
`localStore` (TTL 24 ч). Рестарт или другой инстанс — `jobStatus(id)` пуст.

**Дальше:** `sharedStore` (`cache_kv`) с тем же TTL; заодно оживить
`outcome: 'queued'` — с JS опрос `pollUntilDone`, без JS `303` на `statusUrl`.

### Бюджет тела: остаток — **P3**

Бюджет доезжает из env до `data-budget` и `ctx.limits`. Не сверено на живом
маршруте: `limits.maxFileSize`/`maxValuesPerKey` в транспорте.

**Дальше:** прогнать форму с бюджетом, объявленным из env, и убедиться, что
`413` приходит от нас, а не от платформы.

## 3. Приложение

### `useHeadSeo` не вызывается ниоткуда — **P3**

`src/components/shell/page.svelte.ts` + реэкспорт: два вхождения, ноль вызовов.
Метаданные страниц не заполняются, подпись обещает реактивность, которой при
SSR не бывает.

**Дальше:** удалить из публичного входа `#components`; вернуть, когда появится
контент-слой с настоящими описаниями.

### `steps`: служебный шаг адресуем — **P3**

`addressable` есть только у модалок. Шаг результата или подтверждения получает
свой адрес и перезагружается по ссылке.

**Дальше:** `addressable?: boolean` в описании шагов, — когда появится первый
служебный шаг. Сейчас все адресуемы by design.

### CSP — **P3**

`kit.csp` не включён: нужны sha256 раннего скрипта, self-host шрифта и
`frame-ancestors` в dev. Разбор — [`docs/design/client-integrity.md`](./design/client-integrity.md).

## 4. Вне кода

- **Браузерные сценарии** `test/browser/*.mjs` не прогонялись: в песочнице нет
  бинарников Playwright. Прогон — на стороне владельца.
- **`#lib/db`**: ACL и generic REST (`src/lib/db/docs/ACL-DESIGN.md`), история
  ручных миграций и вычисляемые поля (`PORTING.md` §3.1) — отложены владельцем.
- **Полный прогон vitest** идёт ~2 минуты на 2 vCPU / 1,9 ГБ RAM без swap;
  в ходе работы гоняется только затронутая область, полный — перед коммитом
  крупной пачки.
