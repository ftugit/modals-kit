# План: доработка списка seed-юзеров — фильтры, поиск по id и подгрузка

Статус: **выполнено** (2026-10-27, утверждено владельцем; push запрещён —
всё локально). База: локальный `HEAD a6271c0` (фикс модалки, ещё не запушен),
`origin/img c80e599` (этап 2 целиком). Этот план — отдельная доработка поверх
выполненного этапа 2 из `docs/plan-seed-list-stages.md`, этапы 3–7 не трогает.

## Заказ владельца (исходные пункты)

1. «Показывать никнейм» — сделать чекбоксом; если схема формы этого не умеет,
   добавить поддержку на уровне всего компонента фильтра.
2. Добавить в том числе поиск по id.
3. У seed-списка убрать отображение номера страницы среди списка.
4. Включить отображение скелетона, пока данные подгружаются.
5. Подгрузка сверху и снизу на 40%.
6. Компонент «Это конец» обновить: показывать, только если хотя бы раз была
   подгрузка.
7. «Порядок» — сверху остальных пунктов формы; справа от него — целое поле
   числа элементов на страницу, лимит 10–100; «Порядок» и число элементов —
   одна строка пополам.
8. Остальные пункты «от и до» — тоже пополам на строку.
9. Посмотреть, как у шапки сайта делается разделение по сегментам; «от и до»,
   «сортировку» и «число элементов» делать по аналогичной технологии, чтобы
   при нехватке места второй сегмент переносился на следующий ряд.

## Пробелы (это и есть работа)

1. **Никнейм — select, не чекбокс**: `SeedUsersFiltersForm.svelte` объявляет
   `users.nick` как `field.select` (''/'1'); тип значений формы
   `SeedUsersFilterValues.nick: string` протекает в модалку, no-JS страницу и
   роут (`users.nick=1`).
2. **Поиск по id на сервере не ищет**: адаптер `listPage` в
   `gateway.server.ts` матчит подстроку только по `seed` (+никнейм при
   включённом параметре). Клиентский `record.texts` id уже содержит, но
   родной поиск — серверный, решает адаптер.
3. **Размера страницы в форме нет; лимиты расходятся с заказом**: роут
   `/users` клампит `users.size` в 1..50, домен — `SEED_USERS_MAX_PAGE_SIZE
   = 50`; URL-адаптер `pageSizes` не передаёт (принимает любое ≥ 1).
   Требуется единый диапазон **10..100** на всех слоях.
4. **`EndRow` показывается без подгрузки**: условие — `idle && hasNext ===
   false && loadedPages.length > 0`, то есть и на единственной странице
   выдачи. Нужен факт хотя бы одной догрузки.
5. **Раскладка формы**: сейчас порядок — на всю ширину, даты — жёсткий
   `grid sm:grid-cols-2` (на узком экране пара не «переезжает» сегментом,
   а перестраивается брейкпоинтом сетки целиком).

## Предлагаемые решения (фиксируются этим планом)

- **Чекбокс**: `field.checkbox({ label: 'Показывать никнейм' })`, значение
  формы — boolean. Модальный путь по-прежнему пишет в адрес `users.nick=1`
  (контракт этапа 2 не меняется); no-JS путь шлёт нативное `users.nick=on`,
  роут принимает оба значения (`'1' | 'on'`), домен получает boolean, как
  сейчас. Без прав поля в форме нет (как сейчас).
- **Поиск по id**: та же одна строка поиска; совпадение — подстрока без
  учёта регистра по `seed`, по `id`, а при включённом никнейме — ещё по
  никнейму. `total` и порции считаются по тому же срезу (механика адаптера
  не меняется, добавляется одно условие в матч). Отдельного поля/параметра
  не заводим.
- **Размер страницы**: поле `users.size` в форме фильтров (не `extra` —
  размер порции живёт в состоянии пагинатора, не в фильтрах среза).
  Модалка применяет: сначала `setExtra` (новый срез с первой порции), затем
  `setPageSize` — порядок важен, чтобы не было промежуточного запроса со
  старым срезом и новым размером. «Сбросить» возвращает и размер к
  умолчанию 10. Не-умолчальный размер считается в счётчике «Фильтры (N)»
  (прецедент этапа 2 с никнеймом). Диапазон 10..100: валидаторы формы +
  `pageSizes: 10..100` у URL-адаптера + кламп роута 10..100 + константы
  домена `MIN/MAX = 10/100`.
- **`EndRow`**: условие дополняется фактом подгрузки —
  `loadedPages.length > 1`. Правка **общего** компонента пагинатора (так
  сформулирован заказ — «компонент обнови»): поведение поменяется у всех
  потребителей `Paginator`, демо пагинатора — в регрессионной пробе.
  Начальная порция, дорисованная догрузкой до конца, строку покажет;
  выдача, целиком уместившаяся в первую порцию, — нет.
- **Раскладка формы** (паттерн шапки: `flex flex-wrap` + сегменты
  `min-w-0 flex-1 basis-44`):
  1. Первый ряд: «Порядок» + «Элементов на страницу» — два сегмента
     пополам; не влезли — второй сегмент переезжает на следующий ряд.
  2. Чекбокс никнейма — своим рядом ниже (при правах).
  3. «Состояние» — своим рядом (при правах на удалённые).
  4. «Создан: с/по» и «Удалён: с/по» — пары сегментов по той же технологии.
  Никакого нового компонента не создаём: сегмент — локальная разметка
  формы (`div`-обёртка вокруг `Field`).

## Дополнение по обсуждению (2026-10-27, зафиксировано владельцем)

- **`replaceLoading` к скелетонам не относится.** Этот проп только
  показывает/прячет дополнительную строку «Загрузка…» (`ReplaceLoadingRow`)
  при `pending.mode === 'replace'`; замену pending-группы данными делает
  `pagesList`/`PageList` независимо от него. Поэтому в реализации
  `replaceLoading` **не трогаем** (остаётся умолчание пагинатора): скелетоны
  включаются одним `renderSkeleton`, лишних флагов не вводится.
- **Скелетон повторяет строку списка.** Скелетоны — отдельный компонент
  пагинатора (`Skeleton` из `#components/paginator`), но их компоновку
  задаёт потребитель сниппетом `renderSkeleton`: для seed-списка это
  flex-ряд сегментов по геометрии `SeedUserRow` (seed — гибкий, далее
  никнейм, права, дата, id), а не один серый прямоугольник.
- **Блок ника у скелетона — только при включённом никнейме** (прямое
  указание владельца): сегмент никнейма в скелетоне рендерится при том же
  условии, что и столбец у настоящих строк (параметр `users.nick=1` в
  текущем срезе, `nickOn` экрана). Выключен параметр — сегмента нет, как
  нет и столбца.

## Критерии приёмки (по пунктам заказа)

1. В форме фильтров никнейм включается чекбоксом «Показывать никнейм»;
   сортировки по никнейму появляются/прячутся от него, выключение при
   выбранной сортировке по никнейму возвращает порядок на `created-desc`;
   без прав чекбокса нет; работает в модалке и на no-JS странице.
2. Поиск по фрагменту id (как виден в строке списка) находит аккаунт;
   `total` честен; поиск по seed и никнейму не сломан.
3. В списке нет разделителей «страница N» ни у загруженных, ни у
   pending-порций.
4. Во время догрузки (вниз, вверх и при замене среза поиском/фильтрами)
   на месте будущей порции — скелетоны, а не пустота и не текстовая строка.
5. Догрузка вниз стартует при входе нижнего сентинела в 40%-зону от низа
   контейнера, вверх — симметрично (при загруженной не-первой странице);
   позиция прокрутки при prepend не прыгает.
6. «Это конец» не показывается, пока не было ни одной догрузки (включая
   выдачу из одной страницы); после догрузки до конца — показывается.
7. «Порядок» — первый пункт формы; справа — целое поле «Элементов на
   страницу»; значения вне 10..100 и дроби не применяются ни в модалке,
   ни без JS; применённый размер виден в адресе (`users.size`) и
   переживает reload.
8. Пары «от/до» — два сегмента в ряд на достаточной ширине.
9. На узкой ширине второй сегмент каждой пары переносится на следующий
   ряд (flex-wrap по образцу `HeaderRowView`), поля не сжимаются в
   нечитаемую ширину и не переполняют контейнер.
