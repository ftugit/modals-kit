## 2026-10-26 · Отказ от прав приходит ДАННЫМИ, а не броском

Решение владельца: «я не хочу отдельную карусель с правами; если по роуту нет
прав, лоадер это видит и передаёт в компонент, а тот вместо своего содержимого
грузит ACL-компонент, который сам разберётся».

### Как это делается (минимум кода)

`load` маршрута НЕ бросает `error(403)`, а возвращает факт как данные:

```ts
export const load = async ({ params, ...event }) => {
  const r = await auth(event).profile(params.id)
  return r.ok
    ? { uid: params.id, profile: r.value, fact: null }
    : { uid: params.id, profile: null, fact: r.fact }
}
```

Компонент решает сам, один раз на всю поверхность:

```svelte
{#if fact}<Acl status={fact.code} backHref="…" />{:else}<ProfileForm uid={uid} initial={profile} />{/if}
```

Если ту же ветку показывают и страница, и модалка — она в одном общем
компоненте (`ProfileScreen`), страница и модалка становятся по две строки.

### Почему так, а не через слот ошибки хоста

`ModalContent.svelte` при `status === 'error'` рисует слот хоста и КОМПОНЕНТ НЕ
МОНТИРУЕТ — значит внутри модалки вызвать `Acl` некому. Бросок `error(403)`
превращает отказ в `{ok:false, reason:'error'}` и убивает возможность показать
экран прав. Слот ошибки хоста остаётся для настоящих сбоев (сеть, 500, нет
маршрута), но в сценарии «нет прав» он не участвует.

### Что из этого следует по приватности

Раз отказ — данные, `load` отвечает 200 и `role_forbidden`/`not_found` можно
различать по-человечески. Рекомендация: чужим без прав отдавать `not_found`
(как уже делает `policy`), `session_expired` — только когда `guard` вернул
`auth.expired`.

### Сколько правок

В `lib/modals` — ноль. В `app.d.ts` (`App.Error`) — ноль. `screenOfFailure` не
нужен. Новый код: поле `fact` в `load` и ветка `{#if fact}` в компоненте.

## 2026-10-26 · Права из модели и форма профиля для любого юзера

Состояние на момент записи: `HEAD 2330b04`, дерево чистое. Правки не начаты —
всё ниже это договорённости и притязания, а не сделанное.

### Задание (словами владельца)

1. `requiredGrants` — права брать **из модели**, а не переписывать списки по
   проекту: поменяли правило в `schema.ts` — поменялось и требование в UI.
2. `ProfileForm` без `uid` работает по текущей сессии. С `uid` проверяет права
   `select` и `update`, и только при них грузит и отправляет данные того юзера.
3. Вопросы по заданию требовались до начала работы (сделано после замечания).

### Ответы на вопросы

| вопрос | ответ |
|---|---|
| откуда форма берёт данные чужого профиля | компонент грузит сам: «сейчас компонент — практически самостоятельный роут» |
| откуда ACL берёт права (без `actorOf`) | права в токене (`perm` рядом с `prof`), 0 запросов на экран |
| у чужого нет строки профиля | не создавать: показать «профиля нет», форма не предлагает создать |
| внутренние роли (`server`) в требовании | отдавать как в модели, без фильтра по каталогу |

### Притязания (что мешает «просто сделать»)

1. `requiredGrants` невозможен без правки публичного API `lib/db`: список ролей
   сейчас в замыкании (`policy.ts`, `roles: (list) => (ctx) => …`). Решение —
   метки на функциях правил (`fn.grants`), поведение правил не меняется.
2. `policy.insert` возвращает `boolean`, остальные — `Filter`. «Права для insert»
   — другой тип вопроса («кому можно вообще»), в задаче про `uid` не участвует.
3. Из модели видно не всё: `access` с `owner()` читается («для чужой строки —
   никому»), `link()` и ручные правила — нет. Для них `requiredGrants` → `null`,
   и UI обязан показать форму: прятать по незнанию нельзя.
4. Владелец проходит без ролей (`ownerOrRoles` = «владелец **или** роль»),
   поэтому гейт нужен только при `uid ≠ свой id`.
5. Права в токене отстают до следующего продления (`accessTtlSec`, до 1 ч).
   Сервер проверяет по БД — задержка только в UI.
6. Гейт — только UX; авторитет у `policy` (`profile.read`/`profile.edit`/`admin`).
7. `server` попадёт в список на экране; это надо оформить словами, а не кодом.

### Открытый вопрос (на нём остановились)

«Компонент грузит сам» упирается в механику: у встроенной формы нет пути
«прочитать данные». Варианты: переиспользовать `task`
(`?__form_id=…&__form_task=…`), либо добавить рядом с формой маленький
`read`-хук по тому же `__form_id`. Рекомендация была — второй вариант.

### Порядок работ, если решат продолжать

1. `lib/db`: метки у правил + `requiredGrants` + `grantsAllow` + тест.
2. `perm` в токене → `VaultSessionMeta.permissions` → `vault.permissions`.
3. `read`-хук, `ProfileForm` с `uid`, гейт по модели, «профиля нет» без создания.
