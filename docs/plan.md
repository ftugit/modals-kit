## 3. Решения владельца (действуют)

**Ревизия хода 261 (решения владельца; код — этот коммит):**

- Step — состояние виджета, адрес — fallback без JS (не роутер): клик с JS меняет шаг
  локально; без JS ссылка честно ведёт на адрес. Ссылка-как-единственный-канал (мой
  недосмотр) закрывала модалку навигацией — репорт владельца.
- Seed при регистрации: с JS генерирует БРАУЗЕР (`generateKeyPair`, не покидает
  устройство) — серверная генерация в JS-пути противоречила
  решению; серверный seed — fallback (no-JS / обновление / deep-link), блок-тексты
  различаются («сделал браузер» / «создал и подписал сервер»).
- Шаги — ОДИН универсальный хост (lib/components/steps): раньше две реализации
  (ручной stepHref у авторизации и useSteps у /fields). Режимы `url`/`local`/`hybrid`,
  не знает про форму — нарезается произвольное содержимое; демо `/steps` (опции и
  режимы), потребители переведены. Бронь ключей глобальна: ключ авторизации —
  `stage` (`step` занят /fields; ошибка брони называет владельца).
- Процесс: browser-all не гонять — только локальные тесты затронутых участков.

**Меню, подмена поля, иконки, картинки (ход 261; код сделан — `a258d8c`):**

- Меню пользователя: пустая шапка после входа — баг (воспроизвести тестом до фикса). Модалка
  `user.menu` и новый роут `/user/menu` рендерят БУКВАЛЬНО ОДИН компонент (тело меню — общий
  файл; обёртки отличаются только callback: закрыть модалку / ссылка). Аватар шапки — круглый
  блок под размер аватара, внутри `img` (ширина 100%, высота auto, круглый); нет картинки или
  грузится — заполнитель. No-JS ссылка аватара ведёт на роут `/user/menu`.
- Seed на шаге регистрации — без `readonly` (решение владельца): шаг живёт в адресе, seed всегда
  серверный. Значение в HTML несёт состояние формы: синхронная запись при связывании (SSR и no-JS
  видят seed), переходы — зеркалом на смену `registerSeed`.
- Вход без копирования: иконка копирования на шаге входа — ошибка разметки (рисовали `CopyInput`
  обоим шагам); seed регистрации всегда делает сервер. Подмена примитива — ТОЛЬКО в слое UI:
  `Field.svelte` получает проп `instead` (компонент); подмена действует при `instead.base === Input`
  (производное декларирует базу module-экспортом; button/select подменой не бывают); `CopyField.svelte`
  — отдельный файл (Input → CopyInput → CopyField, образец — `PasswordField`); в `AuthWidget` —
  `<Field of={bound.f.seed} instead={step === 'register' ? CopyField : undefined} />`, на входе —
  обычный input. `lib/form` не трогается: дескриптор поля без UI (владелец: «форма жёстко
  прописывает компонент» — это делает слой `components/form`).
- Таймер создания аккаунта: `holdSeconds` 5 → 2 (`config.ts`).
- No-JS блок на шаге регистрации: seed генерирует и подписывает СЕРВЕР, виден в HTML страницы —
  не открывать форму в общих/публичных местах (утечка seed = доступ к аккаунту).
- CopyInput: успех — иконка «выполнено», отказ браузера — «восклицание»; обе держатся 5 с и
  возвращаются; смена — только по факту записи в буфер; в эти 5 с кнопка не нажимается.
- Профильная форма («не сохранялась с нескольких раз», шаги и URL): разбор и план починки —
  `design/profile-form-fix.md`; унификация шагов НЕ заказана.

**Коллекция с полями от пользователя** (ходы 222–228; сделано: поле `field.fields` и
`defineForm({ from })` — README `lib/form` «Набор полей от пользователя», живой пример — `/fields`):

- Набор полей — **поле формы** в том же списке, что `text`, `number`, `email`:
  `field.fields({ label, max, rules, kinds })`, а не отдельная функция (ход 227). Значение —
  список созданных полей, пределы проверяет форма на обеих сторонах.
- Сохранённый набор снова становится формой — как есть или с полями из кода (набор + название +
  файл), ход 228: `defineForm({ from: saved, fields })`.
- Форма поле набора **сама не рисует** (ход 234), генератор полей и кнопок не расставляет (ход
  235): цикл, место «+ поле», обёртки и классы на обоих этапах — в разметке приложения. Сделано в
  ходе 236: хук `fieldSet` (места и пропсы кнопок), `form.from()` (поля набора в форме записи),
  кнопки набора без JS — отправка с намерением, пустого места заранее нет, ключи мест случайные.
- Запись = название + файл + значения по ключу; подпись показ берёт из текущего набора (ход 233).
  Ключи с записями форма по умолчанию не сверяет — по желанию это проверка приложения (PG jsonb:
  новый или сменивший вид ключ — только если ни у одной записи его нет; удалённый нельзя занять,
  пока записи его держат). Пример — README `lib/form`.

- Проверка идёт в момент записи. Когда правила коллекции стали строже, старые записи никто не
  перепроверяет и не считает; при правке запись обязана пройти новые правила.
- Пределы (длина по умолчанию, потолок длины, число полей) задаются в настройке. Своих чисел у
  библиотеки нет: отсутствие ключа, `undefined`, `null`, `false`, `''` — предела нет.
- Пределы есть у каждого валидатора схемы — на его аргумент (`maxLength`, `minValue`, …), а не
  только на длину. Число может быть отрицательным, если схема это позволяет; аргумент вне
  пределов заменяется ближайшей границей, отсутствующее правило с `default` добавляется.
- Вес формы (128 полей, 2 МБ запроса) — не забота приложения: при нужде его поднимают на сервере
  (`policy.limits`, `Limits`).
- Демо `/fields` хранит один набор полей и одну запись в `#lib/cache` (область `fields-demo`),
  таблиц в базе ради этого не заводится (ход 224).

**Автоматика модели `lib/db`** (сделано, ходы 216 и 219; как пользоваться — README `lib/db` §7):

- `null`, `''`, `undefined` и отсутствие ключа в `timestamps` — одно и то же: поле выключено.
- Разовое отключение — колбэк с временным экземпляром модели (`without(paths, fn)`): клон модели
  в памяти, собранный из той же схемы, где выключенное заменено на `null`. Пути — ключи схемы;
  `without` только сужает; клон не участвует в синхронизации базы. Снаружи поведение узнаётся у
  модели (`behavior()`), не через `ctx`.
- Права — два ключа (`policy` — строки, `grants` — поля). Нет маски — нет защиты; модель без
  прав — выбор разработчика.
- Защищаемся от пользователя модели, не от разработчика (ход 204). `insert`/`update` никогда не
  пишут системные поля; «удалить» через `update` нельзя. Писать системные поля — отдельный ключ
  `protect` (ход 206).
- `raw(fn)` — сырой экземпляр: ничего не фильтрует, не проверяет и не дополняет, и при чтении
  (ход 206–207). Ход 219: связанные записи (`include`) у него тоже сырые; `estimate` работает и
  считает удалённые; `cursor` у него выключен.
- Удаление (ходы 207, 209, 219): `delete(ctx, id)` удаляет одну запись; `{ hard: true }` —
  навсегда (бывшее имя `force` отклоняется); `{ chain: true }` — вместе с цепочкой в одной
  транзакции, ответ — удалённая запись. `chain(ctx, id)` собирает модели, id и права без
  удаления, `plan.delete({ hard })` удаляет. Полный корень — вся цепочка навсегда; мягкий —
  каждое звено обязано уметь мягко, иначе ошибка с именем модели и ничего не удалено. С конца,
  корень последним, ошибка — откат. Каскады `onDelete` из ссылок убраны. Гонку при мягком
  удалении не усложнять (ход 211).
- Ключи доступа (ходы 214–215): права работают по переданным ключам. Без ключей — всё (ORM, не
  API); создание — все ключи обязательны; изменение и удаление по id — достаточно одного
  разрешающего ключа. Мягкое удаление — не права. Свои комментарии в закрытой коллекции видны,
  править нельзя — нормально.

**Формы и БД:** схема задаётся в модели, валидаторы формы генерируются из неё (`formParams`);
метку проверки ставит `ctx.pick(keys)` в `execute`; лишнее поле в записи — `forbidden` (ход 185).

**Автообновление** (всё внесено в `design/live-update.md`): ключ среза `page.asof`; порция новых
в курсоре закрывается по размеру; скользящее продление указателя; признак опроса выводится из
`timestamps`; удалённая строка в срезе исчезает. Опрос только у края и только в пределах
загруженного; часы клиента не используются; запись, выпавшая из фильтра, не помечается;
`ctid` как идентификатор не годится. Удалённые по умолчанию не читает никто; право — объектом.

## 6. Известные ограничения (приняты, не ошибки)

- Новый CHECK на существующей таблице — `NOT VALID`: старые строки не проверяются.
- Типы колонок сравниваются по таблице синонимов: редкий тип с модификатором может дать ложную
  «смену типа» — это конфликт, не потеря данных. Ручное изменение схемы при совпавшем отпечатке
  не замечается.
- Прокси, который копит ответ целиком, отдаст строки хода долгой операции разом в конце — данные
  те же, без живого процента. Vercel отдаёт поток как есть.
- Полоса загрузки байтовой задачи без подписи показывает «100%» — принято.
- Повтор в строке ошибки и чипы фильтров спиннера не получили: исчезают в момент клика.
- Чат-режим в `/db-demo` не сделан сознательно: там витрина «страницы + курсор», чат показан в
  демо-пагинаторе. Поиск без учёта регистра в демо выключен (включается одной строкой в
  `field.filters`).
- Строка, созданная между загрузкой списка и запросом отметки, пилюлей не покажется — её
  покажет следующая загрузка.
- `raw` не умеет `cursor` (значения полей сортировки уходят клиенту в указателе), `restore`,
  `validator`, `without`.
- Безопасность хоста БД — задача оператора: в production TLS, пароль/SCRAM, роль приложения
  без `SUPERUSER`/`BYPASSRLS`.
- Порядок CSS-переменных темы UnoCSS между сборками недетерминирован: CSS сравнивать по набору
  правил, не побайтно.
- Песочница: холодный `vite dev` упирается в нехватку памяти на `/db-demo`; `/tmp` лежит в
  памяти — базы предпросмотров (`/tmp/e2e-db*`) удалять после проверок.
