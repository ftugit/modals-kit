## 3. Решения владельца (с последнего отчёта по `task-state.md`)

**Автоматика модели** (`design/model-automation.md`; «делай» отозван владельцем — сначала аудит):

- `null`, `''`, `undefined` и отсутствие ключа в `timestamps` — одно и то же: поле выключено.
- Разовое отключение — колбэк с временным экземпляром модели и списком ключей автоматики;
  отключить можно всё, что модель делает сама или по сценарию, вплоть до прав доступа.
- Внутри колбэка экземпляр сообщает, что реально выключено; снаружи поведение узнаётся у
  модели, не через `ctx`.
- Права — два ключа (`policy` — строки, `grants` — поля).
- Механика: временный экземпляр — **клон модели в памяти**, собранный заново из той же схемы,
  где отключаемые опции заменены на `null`. Код самих операций ничего не проверяет и не
  переключает — работает обычная модель с другой схемой.
- Ключи `without` — пути в схеме. `without` только сужает (нет `protect`); клон не участвует в
  синхронизации базы; подпись курсора к выключенному не привязывается.
- `null` в правах — одинаково в клоне и в обычной схеме; модель без прав — выбор разработчика.
- `deletedAt: null` в клоне — удаление навсегда и чтение удалённых.
- Даты и другие системные поля пишутся отдельной функцией записи системных полей (план —
  `model-automation.md` §9); будущие функции правки опций — тоже клоны, цепочкой из `without`.
- Ход 204: защищаемся от пользователя модели, не от разработчика. `insert`/`update` никогда не
  пишут системные поля (id, время и др.); «удалить» через `update` нельзя. `writable` — сырая
  запись: без фильтров, проверок и дополнений. Нет маски права — нет защиты. Каскад при полном
  удалении должен работать; при мягком — опция.
- Ход 206: `protect` — отдельный ключ; сырой клон выключает всё, и чтение тоже (имя — на
  усмотрение, предложено `raw`). Каскад — функция модели + опция (выкл. по умолчанию); без
  каскада ошибку даёт база; каскад проверяет права на каждом звене и называет, где упёрся;
  одна транзакция, удаление с конца; способ удаления в цепочке одинаковый; «не глядя» —
  через клон без прав.
- Ход 207: сырой клон — `raw`; из ссылок убрать `onDelete: cascade/set null`. Цепочка — отдельная
  функция (модели, id, права); `delete` удаляет одну запись по правилам модели, способ — опцией
  (мягко / полностью); с цепочкой — с конца, корень последним. Полное — цепочка полностью;
  мягкое — все звенья обязаны уметь мягко, иначе ошибка и ничего не удалено.
- Ход 209: флаг принадлежности `chain: true`; связи из `references` + список моделей у `createDb`;
  `chain` собирает, решает `delete`; выключенное у корня переходит на цепочку; имена `chain`,
  `canDelete`, `force`. Удаление — с конца клонами `without` (при полном — без мягкого удаления);
  ошибка SQL — откат и ошибка базы.

**Автообновление** (всё внесено в `design/live-update.md`):

- Ответы на вопросы плана (§9): ключ среза `page.asof`; порция новых в курсоре закрывается
  по размеру порции; указатель — скользящее продление; признак опроса выводится из
  `timestamps`; удалённая строка в срезе страниц исчезает.

- Режим страниц: ключ среза, чтобы содержимое страниц не смешивалось с новыми данными;
  новее среза — сброс пагинатора (кнопка сброса есть).
- Курсор: новые строки из автообновления — отдельная «страница» со своим ключом; в адресе —
  ключ читаемой порции; перезагрузка даёт срез с нового сообщения, дальше обычными порциями.
- Автообновление работает только у края (лента — верх, чат — низ, страницы — первая); срез
  не у края → опроса нет, пока пользователь не догрузит до края.
- Изменённые строки — только в пределах загруженного и рядом с пользователем; вдали от края
  не спрашивать. Дополнительно — опрос изменений, когда пользователь прокручивает.
- Что опрашивать, решают поля таблицы: нет `updated_at` — только новые.
- Системные поля в `lib/db` владелец просил раньше — делать.
- Soft delete нужен; чтение удалённых — только админ (админа пока нет).
- Часы клиента не используются.
- Запись, выпавшая из фильтра после изменения, не помечается.
- Удаление строки-закладки курсор не ломает (закладка — значения, не ссылка); `ctid` в PG
  как идентификатор не годится.

## 6. Замечено попутно

- **Права на изменение записей демо (`posts.ts`):** `policy.ownerOrRoles('id', ['editor'])` сравнивает
  id записи с id пользователя — у записей нет поля владельца, поэтому владелец свою запись
  изменить не сможет. Сейчас не проявляется: изменения в демо нет, пользователь без id. План:
  при документе авторизации добавить поле владельца (`author_id`, `ownerField`, значение из
  `ctx.principal.id`) и передать его в `ownerOrRoles`.

- Часть А плана загрузки: объявления для экранных чтецов (`aria-live`) отложены; повтор в
  строке ошибки и чипы фильтров спиннера не получили (исчезают в момент клика).
- Полоса загрузки байтовой задачи без подписи показывает подпись «100%» — принято как есть.
- `test/browser/loader.mjs` не отформатирован Prettier — было до меня, проверки тесты не
  форматируют.
- Мой скрипт проверок (`~/.agent/probes/gate.sh`, вне проекта): после сброса песочницы
  тяжёлые файлы тестов базы запускаются каждый отдельным процессом — иначе не хватает памяти.
  Состав тестов не менялся (1046/1046).
- Исправление сброса вскрыло скрытую опору курсора на этот сброс: указатель следующего шага
  есть в снимке сервера, но не в адресе, и первое сравнение после оживления снимало его
  (первый клик «дальше» уходил без указателя). Теперь при первом сравнении отсутствие
  позиционного ключа в адресе его не снимает. В адресе после серверной отрисовки указателя
  по-прежнему нет — это та же тема, что потеря прочитанного (§4 `live-update.md`).
- Бюджеты веса подняты (ход 198): весь JS 245.5 → 246.5, immutable 259 → 260, `/db-demo`
  204.5 → 205.5 (факт 245.7 / 259.3 / 204.5+). Причина — модель `posts` едет в браузер вместе
  с `defineResource`, который теперь разворачивает `timestamps`.
- Ответ `/api/db-posts` теперь несёт и `updated_at`, `deleted_at` (поля читаемы). Понадобятся
  опросу (шаг 5); `deleted_at` у публичного чтения всегда `null`.
- `/tmp` в песочнице лежит в памяти: базы предпросмотров (`/tmp/e2e-db*`, ~40 МБ каждая)
  доводили тяжёлые тесты базы до OOM. Удалять их после браузерных проверок.
