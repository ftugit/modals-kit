## 3. Решения владельца (с последнего отчёта по `task-state.md`)

**Автообновление** (всё внесено в `design/live-update.md`):

- Режим страниц: ключ среза, чтобы содержимое страниц не смешивалось с новыми данными;
  новее среза — сброс пагинатора (кнопка сброса есть).
- Курсор: новые строки из автообновления — отдельная «страница» со своим ключом; в адресе —
  ключ читаемой порции; перезагрузка даёт срез с нового сообщения, дальше обычными порциями.
- Автообновление работает только у края (лента — верх, чат — низ, страницы — первая); срез
  не у края → опроса нет, пока пользователь не догрузит до края.
- Изменённые строки — только в пределах загруженного и рядом с пользователем; вдали от края
  не спрашивать. Дополнительно — опрос изменений, когда пользователь прокручивает.
- Что опрашивать, решают поля таблицы: нет `updated_at` — только новые.
- Системные поля в `lib/db` владелец просил раньше — делать.
- Soft delete нужен; чтение удалённых — только админ (админа пока нет).
- Часы клиента не используются.
- Запись, выпавшая из фильтра после изменения, не помечается.
- Удаление строки-закладки курсор не ломает (закладка — значения, не ссылка); `ctid` в PG
  как идентификатор не годится.

**Отложенные пункты:**

- REST и права доступа — сначала авторизация.
- Разбивка документации `lib/db` на страницы — когда кодовая база стабилизируется.
- Демо-панель — «малой кровью», по аналогии с фильтрами: UI, схема и `lib/form` в связке.
- Поле, которое добавляет пользователь, — изучить заново с учётом обновлённой формы; у формы
  должна быть схема поддерживаемых валидаторов, чтобы будущее поле могло иметь любой из них.
- `refresh({ keepWindow })` — заменяется планом `live-update.md`.

## 6. Замечено попутно

- Часть А плана загрузки: объявления для экранных чтецов (`aria-live`) отложены; повтор в
  строке ошибки и чипы фильтров спиннера не получили (исчезают в момент клика).
- Полоса загрузки байтовой задачи без подписи показывает подпись «100%» — принято как есть.
- `test/browser/loader.mjs` не отформатирован Prettier — было до меня, проверки тесты не
  форматируют.
- Мой скрипт проверок (`~/.agent/probes/gate.sh`, вне проекта): после сброса песочницы
  тяжёлые файлы тестов базы запускаются каждый отдельным процессом — иначе не хватает памяти.
  Состав тестов не менялся (1046/1046).
- Исправление сброса вскрыло скрытую опору курсора на этот сброс: указатель следующего шага
  есть в снимке сервера, но не в адресе, и первое сравнение после оживления снимало его
  (первый клик «дальше» уходил без указателя). Теперь при первом сравнении отсутствие
  позиционного ключа в адресе его не снимает. В адресе после серверной отрисовки указателя
  по-прежнему нет — это та же тема, что потеря прочитанного (§4 `live-update.md`).
- `/tmp` в песочнице лежит в памяти: базы предпросмотров (`/tmp/e2e-db*`, ~40 МБ каждая)
  доводили тяжёлые тесты базы до OOM. Удалять их после браузерных проверок.
