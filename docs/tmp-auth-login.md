# Временно: вход падает после создания аккаунта

Удалить, когда правка окажется на живом сервисе и повторный вход создаст сессию. Это запись передачи, не контракт модуля.

## Задача

Разобраться, почему не работает авторизация. Прямое подключение к БД и сброс оба допустимы; способ не спрашивать. Базу не сбрасывать, пока факт не сужен. Seed и URI не печатать.

## Факт

Живой POST `intent=login` на `https://site--pzlb--c7ggfx29x5k8.code.run/user/auth` отвечает HTTP 500, «Операция не выполнена», куки нет. Лог Northflank: `[form] outcome-unknown null`. Стека нет: внутренний catch `src/lib/form/server.ts` глотает исключение `execute`, а `notifyResultErrors` при `outcome === 'unknown'` всегда шлёт `cause: null`.

Три аккаунта за 2026-11-09 созданы, сессий у них нет:

- `02d85543-6467-43d9-aaef-72ed6ddd5f54` — 02:01:52Z
- `0fd2c386-6a56-4f30-8542-971b4d41c8ad` — 05:12:22Z
- `270a2e06-c0d4-4a99-baaf-1d27e1c3bee0` — 05:12:37Z

В `cache_kv` две записи `scope=auth-challenge-nonce`, срок `05:14:22Z` и `05:14:37Z`. Это `clock_timestamp() + challengeTtlSec` (120 с) в момент `consume`. Значит оба POST прошли `blocksOf` и `consumeChallengeNonce` и упали после них. Строк сессии нет, значит throw в `openSession` → `sessions.create`, не в профиле и не в nonce.

`sessionsAdapter.create` передаёт `id`. У `user.session` `id` — `primaryKey` и `createValue`. `draftInput` отвергает такое поле, если не выключен `protect` (`src/lib/db/validation.ts`, тест `protect` в `src/lib/db/test/db-rules.test.ts`, README lib/db). Проба слоя: `insert` с тем же набором полей и ролью `server` бросает `forbidden` до SQL; без `id` и с `without(['protect'])` запрос уходит в драйвер. `select` сессий и чтение профиля владельцем с пустыми правами запрос строят.

Сессия 2026-11-05 создана до коммита `458aea2` (2026-11-07), который начал передавать `id`. Деплой Northflank 2026-11-09T01:19Z уже содержит этот коммит.

## Решение

`create` вставляет строку через `api().without(['protect'], …)`, как README lib/db велит передавать свой `id`. `raw()` не использовать: он снимает и маски, и схему. `id` из входа не убирать: порт обещает записать переданную запись, а `openSession` уже выдал этот uuid.

Пустые аккаунты не удалять. Повторный вход тем же seed найдёт строку и откроет сессию после деплоя.

Логгер формы не трогать в этом шаге: `cause: null` — отдельное поведение, в исключении могут быть значения запроса.

## Проверка

- Проба слоя, фейковый драйвер, без записи в Northflank: insert с `id` → `forbidden`, 0 SQL. Без `id` и с `without(['protect'])` запрос уходит в драйвер.
- PGlite, та же схема: обычный insert с `id` → `forbidden`; `without(['protect'])` сохраняет переданный `id`, select по `jti` его находит. Команда: `/tmp/auth-probe/probe-pg.mjs`, последняя строка `MATCH yes`.
- `npx vitest run src/content/user/sessions.server.test.ts` на Node 22.23.4: 4 passed, включая «сервер пишет свой id сессии только без protect».
- `npx vitest run src/content/user` убит ядром (вероятно нехватка памяти), итог не считать.
- `npm run check` и полный `vitest` не запускались.
- Живой POST не повторять, пока правка не на сервисе: каждый проход плодит ещё один пустой `user_auth`.
