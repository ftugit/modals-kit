# Сессии и права `user_auth` / `user_session` (памятка)

Статус: **в планах** (памятка без разбивки на этапы; реализация — только по отдельной команде владельца).

---

## Что уже реализовано в коде

- Модель `user_session` в `src/content/user/schema.ts`: `jti`, название устройства, хеш текущей подсети и история подсетей, `last_seen_at`, мягкое удаление при отзыве.
- Доменные функции в `src/content/user/auth.ts`: `listSessions`, `revokeSession`, `logout`, `logoutAll`, настройка привязки к подсети `session.ipLock` через `user_config`.
- Хранение токенов в `HttpOnly`-куках, публичные метаданные сессии и грантов `permissions` в `vault` (через короткоживущую куку `auth_tmp` за `0` лишних запросов к БД) и межвкладочная синхронизация обновления.
- Грант `account.readDeleted` уже вписан в `user_auth` (конъюнктивное чтение удалённых строк через `selectDeleted`).

---

## Что остаётся сделать

### 1. Пользовательский интерфейс активных сессий (устройств)

- Универсальный компонент просмотра активных сессий и устройств в `src/content/user/ui/`:
  - отметка текущего устройства, название клиента/браузера, время последней активности (`TimeAgo`), индикация смены подсети;
  - отзыв конкретной сессии и завершение всех остальных / всех сессий.
- Пара «модалка + маршрут» (работа с JavaScript и нативным `POST` без JavaScript):
  - для собственных сессий текущего пользователя (точка входа из меню пользователя и карточки профиля);
  - для просмотра и отзыва сессий целевого пользователя при наличии прав (`session.read`, `session.edit`, `admin`).

### 2. Нативные политики моделей `user.auth.v1` и `user.session.v1` (`defineAcl`)

- Перевести человеческие операции `AuthPorts` с системного контекста `SYSTEM` на контекст актора (`principalOfRow`), чтобы сами модели исполняли пирамиду прав наравне с `user_block` и `user_profile`:
  - `user_auth`: `account.read`, `account.edit`, `account.readDeleted` через `defineAcl`, `grants(auth)`, `checkGrants` и реактивный `useGrants` в UI (выдача `permissions` и защищённые системные поля остаются закрытыми за `admin`);
  - `user_session`: `session.read` (чтение чужих активных сессий), `session.edit` (отзыв/мягкое удаление чужих сессий) и при необходимости `session.readDeleted` по образцу `account.readDeleted`.
- Системный контекст `SYSTEM` оставить только внутренним механизмам без актора-человека: вход и проверка `challenge`, фаервол блокировок (`blocksOf` / `guard`), восстановление по `seed`, отложенная зачистка `sweepDeletions`.
