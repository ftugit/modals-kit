# План: auth и session — на рельсы прав модели

Статус: **запланировано** (2026-10-29, по итогам
`docs/audit-delete-rights-2026-10-29.md`, находки A1/A2). Берёмся,
когда будем делать компоненты сессий (устройств): без UI перенос
политик даст только тесты, а контракты показа всё равно переделывать.

## Проблема

Каталог прав обещает то, чего модели `user.auth.v1` и
`user.session.v1` не исполняют:

- `account.edit` нет ни в одной политике аккаунтов; `account.read`
  есть только в `select`, запись и удаление — владелец/`server`/`admin`.
- `session.read`/`session.edit` нет ни в одной политике сессий:
  только владелец, `server`, `admin`.
- Операции с правами домен ведёт системным портом (`AuthPorts`
  исполняет `SYSTEM`-контекстом, проверки — кодом домена в
  `accounts.ts`/`admin.ts`), а не контекстом актора через модель.

Исключение, закрытое раньше: `account.readDeleted` уже выделено и
вписано в `auth` (грант `readDeleted` + политика `selectDeleted`
слоя) — это образец для остальных прав.

## Цель

Права `account.*` и `session.*` исполняет модель нативно, как уже
исполняет `user.block` и `user.profile.v1`: актор ходит своим
контекстом, политики/`selectDeleted`/маски слоя решают. Системный
контекст остаётся только внутренним механизмам: вход и фаервол,
исполнитель удалений (`sweepDeletions`), восстановление по seed —
там, где актора-человека нет по смыслу.

## Этапы

1. **Политики auth.** `account.read`/`account.edit`/`account.readDeleted`
   по операциям: чтение живых, чтение удалённых (`selectDeleted`),
   запись служебных полей (маски `permissions`/`seed` не ослаблять:
   выдача прав — только `admin`, как сейчас), удаление/восстановление
   (edit включает мягкое удаление; окончательное — связка
   edit + `readDeleted`, слой это уже держит).
2. **Политики session.** `session.read` (чужие живые),
   `session.edit` (завершение чужих сессий = мягкое удаление),
   при необходимости `session.readDeleted` отдельным правом —
   по образцу `account.readDeleted`, не раньше, чем UI устройств
   покажет, кому это нужно.
3. **Порты и адаптеры.** Человеческие операции `AuthPorts` перестают
   исполняться `SYSTEM`: адаптер прокидывает контекст актора
   (`principalOfRow`), домен перестаёт проверять права вручную там,
   где их уже держит модель (проверки остаются только для фактов
   домена и показа). Внутренние вызовы (`blocksOf`, guard, sweep)
   системный контекст сохраняют.
4. **Тесты.** PGlite-политики по каждой модели: право без чтения,
   чтение без записи, связка на окончательное удаление, владелец
   против чужого. Доменные тесты — на фейках с акторским контекстом.

## Не входит

- UI сессий/устройств (отдельная работа, ради неё план и отложен).
- Схемы в данных для auth/session (права — каталог, как у блока).
- Смена состава каталога сверх уже добавленного
  `account.readDeleted`.

## Критерии приёмки

- Каждая строка каталога `account.*`/`session.*` встречается в
  политиках или масках своей модели (страж `grantedInSchema`
  расширить на модели auth/session тестом, как сейчас на блок).
- Человеческая операция без права отклоняется слоем на PGlite-тесте
  при прямом обращении к ресурсу, минуя домен.
- Гейты: `npm run check` 0/0, layer-guard OK, полный vitest,
  `npm run build`.
