# Временно: фильтр списка в sidebar

Удалить, когда вернёмся к вопросу. Это запись исследования, не план к исполнению и не контракт `Listing`.

## Что решено

Положение фильтра зависит от текущего рендера, не от догадки `Listing`.

- Модалка опцию не передаёт. `Listing` всегда рисует кнопку в `Surface`.
- Страница может передать зону sidebar (`top` / `middle` / `bottom`). Это не обязательно.
- Видимость — классы, не `useIsMobile`. Зона есть — форма в sidebar через `mergeSlot` с базовым `offset: 999` и остаётся на любой ширине. На `max-lg` фильтр в sidebar скрыт, кнопка в `Surface` показана. На широком экране форма видна, кнопка скрыта. Зоны нет — только кнопка. `ready` нет, пустой слот про запас не рисовать.
- Несколько списков не склеивают фильтры. У каждого своя зона, либо кто-то зону не получает и остаётся с кнопкой.
- `Listing` не вызывает `useModal()` и `tryUsePage()`, чтобы понять, где он. Контекст страницы есть и у модалки: она живёт под тем же layout.

## Цепочка опции

Проп сам не протекает: у каждого узла закрытый список пропов. Его надо объявить и передать дальше.

Страницы:

- `/users` → `SeedUsersList` → `Listing`
- `/blocks` → `BlocksList` → `Listing`
- `/user/[id]/blocks` → `BlocksList` → `Listing`
- `/users/pick` → `UserPicker` → `SeedUsersList` → `Listing`. Если этой странице понадобится sidebar, проп должен пройти и через `UserPicker`: там два списка.

Модалки опцию не передают:

- `SeedUsersModal` → `SeedUsersList`
- `BlocksModal` → `BlocksList`
- `UserPickerModal` → `UserPicker` → `SeedUsersList`

`UserPickerSteps` никуда не подключён.

## Sidebar

Канал уже есть: `useSidebarSlot` / `registerSidebarSlot`, зоны `top` / `middle` / `bottom`, плюс `auto`. `useSidebarSlot` смотрит `enabled` один раз и за шириной не следит. Ширину для фильтра списка хук не решает: форма регистрируется, если зона передана, а мобильный режим прячет её классом.

`auto` — не зона Listing, а режим `registerSidebarSlot`. Занятость зоны видна по её списку: не-каркасная регистрация. Каркас layout (`frame`) во всех трёх зонах виден, но для `auto` их не занимает. Свободные зоны заполняются сверху вниз, в порядке регистрации `auto`. Нет ни одной занятой зоны — `auto` не рисуется и пишет в консоль браузера `[sidebar] auto: нет занятого слота, блок не показан`. Свободной зоны не осталось — то же молчание в вёрстке и `[sidebar] auto: свободной зоны нет, блок не показан`. Отдельной серверной функции для жалобы нет.

Каркас сам занимает все три зоны копией шапки (пользователь, то же меню, футер). Форма страницы встаёт после него: базовый `offset: 999`, зона складывается через `mergeSlot`. На широком экране панель в документе, на узком это шторка. Мобильный режим фильтра — `max-lg`, не хук. `ModalHost` ширину не читает, ему передают `isNarrow`.

## Чего не делать

- Не угадывать носитель внутри `Listing`.
- Не объединять схемы фильтров.
- Не класть кнопку в шапку сайта.
- Не учить `Surface` слову «фильтр».

## Этапы

Граница, чтобы этапы снова не смешались.

Первый этап — где форма. Страница передаёт зону (`top` / `middle` / `bottom` / `auto`) по цепочке до `Listing`. Модалка не передаёт. `tryUsePage` здесь только реестр слота, не догадка носителя. `/users`, `/blocks` и `/user/[id]/blocks` передают `middle`: форма длинная, эта зона скроллится. `/users/pick` зону не передаёт. Шаг «выбранные» в пикере зону не получает: тот же пагинатор. Видимость узкий/широкий — не этот этап, а третий.

Второй этап — нарезка меток схемы. Не генерация полей и не `PopupSteps`.

UI задаёт автор в компоненте формы. Кусок одного ключа схемы оборачивается `FilterBlock`. Оболочка `display: contents`, сетка и размеры панели не меняются. Несколько ключей рядом держит обычный блок разметки, не один `FilterBlock`.

Метка берётся из той же схемы, что форма: `FilterBlock` не получает подпись. Он читает имена контролов внутри, `parseCatalogFilterPath` даёт ключ, подпись — `fields[].label` этой схемы. Поле без блока: пункт метки есть, всплывашки нет. Два ключа в одном блоке — это не общая метка: блок не регистрируется, всплывашки нет. Пустой блок (поля нет у источника) тоже ни к какой метке не относится.

Всплывашка — `Floating` в режиме `flow`. Открытая метка забирает уже собранный блок, второй копии полей нет. На узком экране лист решает хост. Без хоста всплывашки нет, поля остаются в форме.

Размер страницы seed (`size`, «Элементов на страницу») в схему каталога не входит. Эта нарезка его не видит.

Одна строка `ActiveFilters` на `max-lg` — косметика чипов, не эта нарезка.

Третий этап — видимость фильтра классами, не хуком. `ready` не возвращать. Пустой слот про запас не рисовать.

Зона передана и есть контекст страницы — форма регистрируется в эту зону и остаётся там на любой ширине. `useIsMobile` регистрацию не снимает и кнопку не прячет. Мобильный режим — `max-lg`, тот же порог, что у панели.

Регистрация — `registerSidebarSlot` с базовым `offset: 999`. Зона складывается через `mergeSlot`. `999` ставит форму после каркаса и после слотов `1`, `600`, `888`, не вместо навигации. Тот же offset перезаписывается: второй список в ту же зону с `999` затирает первый. Страница передаёт одну зону одному списку. Пикер и модалка зону не передают: слота нет, кнопка видна на любой ширине.

В sidebar фильтр скрыт, когда работает мобильный режим: обёртка формы в слоте носит `max-lg:hidden`. Каркас панели этот класс не прячет. Кнопка в `Surface` при занятой зоне носит `lg:hidden`: на узком экране показана, на широком нет. Оба узла в HTML. Без JavaScript узкий экран показывает кнопку, широкий — форму в sidebar. Кнопка полей не несёт: без JavaScript это ссылка на страницу фильтров.

Чипы и `FilterBlock` не переписывать. Скрытие классом форму не размонтирует: блок остаётся, метка чипа может открыть его, пока фильтр в sidebar скрыт. Второй копии полей в списке нет. Раскладку из схемы не собирать.

Код: слот с offset `999`, обёртка формы `max-lg:hidden`, кнопка при занятой зоне `lg:hidden`. Хук ширину не решает.

## План хода

Этот план — этап 2. Он снят. Этап 3 — раздел выше, в коде не начат.

1. `Listing`: между поиском и пагинатором список активных фильтров. Ключи те же, что у счётчика кнопки. Подписи из описания формы списка, не вторая схема. Чип снимает значение. Пункт метки открывает `FilterBlock`, только если блок смонтирован. Форма только в закрытой модалке — блока нет, всплывашки нет, чип снимает.
2. Реестр блоков по имени списка, не контекст `Listing`: форма рисуется в sidebar и в модалке, не ребёнком списка.
3. `FilterBlock` понимает и ключ схемы каталога, и имя поля формы списка. Один ключ на блок. Два ключа — не регистрировать.
4. Обернуть каждый ключ во всех формах: Шикимори, Rick and Morty, seed, блокировки. Сетка и `flex` остаются снаружи. Скрытые служебные поля не оборачивать. Демо-каталог в git не класть.
5. Не пушить. Не дублировать поля. Не генерировать раскладку.

Сделано в рабочем дереве. Снимок — отдельный локальный коммит на `img`. Демо в `img` не коммитить: это модуль `modules`.
