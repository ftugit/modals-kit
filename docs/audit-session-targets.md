## 1. Настоящее нарушение: карточка устройства выбирает адрес по клиентскому зеркалу

| Файл | Строки | Что делает | Почему нарушает правило |
|---|---|---|---|
| `src/content/user/ui/SessionCard.svelte` | 66–70 | `cardRoute`: если владелец строки не равен `vault.principal`, строит адрес чужой карточки, иначе свой | Адрес шага подтверждения зависит от клиентского зеркала, а не от переданной цели |
| `src/content/user/ui/SessionCard.svelte` | 71–72 | `exitNextHref` / `exitBackHref` в модалке используют `cardRoute` | Шаг подтверждения уходит на адрес, выбранный по зеркалу |
| `src/content/user/ui/SessionCard.svelte` | 76 | `foreign = session.authId && session.authId !== vault.principal` | Признак «чужое» вычисляется клиентом |
| `src/content/user/ui/SessionCard.svelte` | 77–79 | `exitAction`: для «чужого» — адрес чужого списка `?/revoke`, иначе `actionHref ?? свой список ?/revoke` | Адрес закрытия игнорирует уже переданный `actionHref` и пересчитывается по зеркалу |
| `src/content/user/ui/SessionCard.svelte` | 82–87 | `renameAction`: `actionHref ?? (foreign ? чужая карточка : своя карточка)` | Переименование хотя бы уважает переданный `actionHref`; закрытие — нет |
| `src/content/user/ui/SessionModal.svelte` | 27–36 | Модалка знает `uid` из параметров и строит готовый `actionHref` переименования | Цель уже передана носителем; карточка должна использовать её, а не зеркало |

**Целевое поведение:** адрес закрытия и адрес шага строятся от переданной цели
(владелец + устройство) или от носителя. Сравнение «моё/чужое» остаётся только для
показа чекбокса/кнопок и имеет серверный запас при пустом зеркале.

## 2. Пограничное: клиент молча меняет набор целей блокировки

| Файл | Строки | Что делает | Почему пограничное |
|---|---|---|---|
| `src/content/user/ui/block-form/BlockFormBody.svelte` | 125–137 | `normalizeSubjects` вычитает `selfId` из целей | Клиент молча уменьшает набор |
| `src/content/user/ui/block-form/BlockFormBody.svelte` | 139–152 | `resolveSeedSubjects` сидирует цели из фильтра и тоже вычитает себя | То же |
| `src/content/user/ui/block-form/BlockFormBody.svelte` | 210, 216, 232, 266, 295, 324, 351, 363 | Вызовы нормализации/сидирования с `vault.principal` | Все точки клиентского вычитания |
| `src/content/user/ui/BlockCreateModal.svelte` | 21–27 | `initialSubjects` фильтрует `s !== vault.principal` | Модалка тоже вычитает себя до передачи в форму |
| `src/content/user/ui/BlocksList.svelte` | 84–91 | `filterUids` вычитает `vault.principal` из фильтра целей | Клиент правит фильтр молча |
| `src/content/user/ui/BlocksList.svelte` | 220, 249 | Использование `filterUids` в сводке/фильтрах | Точки применения |
| `src/content/user/blocks.ts` | 227 | Сервер отказывает, если цель совпадает с актором | Серверный запрет уже есть |
| `src/content/user/blocks.ts` | 358 | Сервер отказывает, если набор целей содержит актора | Дыры нет; клиентское вычитание — не граница безопасности |

**Целевое поведение:** клиент не вычитает цель молча. Сервер отказывает внятным кодом;
UI может показать, что цель исключена, но не меняет выбор без ведома человека.
Доменная механика и ACL блокировок не меняются.
