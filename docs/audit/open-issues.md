### `OI-22` — гибридное поле файлов: превью, компактный ряд, прогресс (**P2**)

**Ожидание:** для `field.files` работает гибридное поле, где видны все выбранные файлы; среди них фото получают браузерное превью, остальные — иконки; компактный режим — один ряд со скроллом; прогресс бара нет, потому что метод фреймворка не даёт.

**Сейчас:**

| Часть | Факт |
|---|---|
| показ выбранных | есть — `FileAttachment` (`src/components/ui/file-attachment/FileAttachment.svelte`) рисует `<ul data-file-list>` из `pickedFiles` |
| превью фото у файлов | есть — `Attachment` в режиме `media: 'auto'` создаёт `URL.createObjectURL(File)` (`Attachment.svelte:158-172`), вид определяется по MIME (`model.ts:215`: `mime.startsWith('image/') → 'image'`), остальные → иконка `ATTACHMENT_KIND_LABELS` |
| компактный ряд со скроллом | **нет** — раскладок всего две: `'row'` → `flex flex-col gap-2`, `'tile'` → `flex flex-wrap gap-2.5` (`FileAttachment.svelte:155-157`, тип `model.ts:11`). Горизонтального ряда с `overflow-x` нет: и список, и плитка переносятся/складываются |
| прогресс в UI | **готов, но не подключён** — `Attachment` принимает `progress` и `progressVariant` и рисует `role="progressbar"` (`Attachment.svelte:57,102,458-465`), `FileField` эти пропсы не передаёт и `itemProps` не использует |
| прогресс загрузки | **физически недоступен на текущем транспорте**: отправка идёт `fetch` (`src/hooks/component-form/transport.ts`), а у `fetch` нет событий прогресса **отправки** (`upload.onprogress` есть только у `XMLHttpRequest`). Тот `report`, что есть (`bind.svelte.ts:788-790`, `transport.ts:41,136`), — это строки стрима **ответа** сервера (`fetchWithTask`/`readTaskStream`, `src/lib/fetch/stream.ts`), то есть прогресс серверной задачи, а не загрузки тела |

**Уточнение по формулировке:** «метод фреймворка не даёт» — верно по факту, но причина не в SvelteKit: тело уходит через `fetch`, у которого нет прогресса отправки. Варианты, если прогресс нужен: (а) `XMLHttpRequest` в транспорте — только для загрузок, с сохранением текущего контракта `Transport`; (б) условная загрузка кусками (`Content-Range`/chunked) с прогрессом по частям; (в) оставить без прогресса, но задействовать индетерминантное состояние `state: 'uploading'` (`Spinner` уже есть, `Attachment.svelte:341`).

### `OI-25` — ошибки по файлам скопом, а не по одной (**P2**)

**Ожидание:** у поля файлов в множественном режиме ошибки показываются списком по всем проблемным файлам.

**Сейчас:** правила возвращают **первую** ошибку: `v.accept` — `filesOf(value).find(f => !types.some(...))` (`validators.ts:352-362`), `v.maxSize` — так же (`:364-372`); проверка содержимого `checkPhotoFile` возвращает один `Issue` (`photo.ts:93-115`). `FieldShell` показывает первую ошибку и список остальных **ошибок правил** (`FieldShell.svelte:55-60`), но не «по файлу».

**Расхождение:** чтобы показать «этот файл тяжёлый, этот не тот формат», нужно по ошибке на файл. Сейчас при пяти плохих файлах пользователь увидит одну строку про первый.

**Что править:** правила для множественных значений должны отдавать по `Issue` на каждый проблемный файл (с `params.name`), а `FieldShell`/`FileAttachment` — раскладывать их рядом с карточкой файла (`itemProps.error` у `FileAttachment` для этого уже есть, `FileAttachment.svelte:29-45`).

### `OI-26` — выбор файлов из разных папок и удаление только через Attachment (**P2**)

**Ожидание:** можно выбрать файлы из разных папок (несколько заходов в диалог), а убрать файл можно только через `Attachment`.

**Сейчас** (`FileAttachment.svelte`):

| Часть | Факт |
|---|---|
| накопление выбора | **нет** — обработчик `onchange` делает `pickedFiles = list` из `e.currentTarget.files` (`:166-173`), то есть каждая новая выборка **заменяет** прежнюю. Выбрать два файла из разных папок за два захода нельзя — первый пропадёт |
| удаление только через Attachment | **да** — единственный путь `removeAt(index)` (`:140-153`) через `DataTransfer` + `change`; в самом `FileInput` кнопки удаления нет |

**Расхождение:** требование «из разных папок» не выполняется. Правится в `FileAttachment`: при `multiple` дополнять `pickedFiles` новыми файлами (дедупликация по `name+size+lastModified`), собирать `FileList` через `DataTransfer` и обновлять `input.files`, чтобы форма уносила накопленное. Побочно это делает `removeAt` единственным способом убрать файл — как и требуется.
