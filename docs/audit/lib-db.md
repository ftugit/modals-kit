## Открытые пункты

- [ ] **F43 — `paths` без границы сегмента.** `sveltekit/handle.ts:28`:
  `pathname === p || pathname.startsWith(p)` — `'/db-demo'` совпадает и с `'/db-demoX'`.
  Исправление известно: `pathname === p || pathname.startsWith(p.endsWith('/') ? p : p + '/')`.
- [ ] **C1 — хук приложения повторяет `dbHandle`.** `src/hooks.server.ts:35`: хук сам
  фильтрует пути и на каждый запрос заново создаёт `dbHandle(...)`. Задумано:
  `export const handle = dbHandle({ db: async () => (await getRuntime()).db, principal: () => DEMO_PRINCIPAL, paths: ['/db-demo', '/api/db-posts'] })`.
  В самом хуке та же граница пропущена у `/api/db-posts` (`startsWith('/api/db-posts')`).

- [ ] **C10-db — типизация перенесённых сценариев.** `src/lib/db/test/ported/*.script.ts`
  исключены из `tsconfig.json` (101 ошибка: `db-followup` 38, `db-lib` 37,
  `db-hardening` 26). Остальной C10 закрыт: тесты и `tooling/db-docs.mjs` проверяются.
  Состав: нетипизированный JS-порт (неявный `any`, `catch (e)` без сужения, `PGlite | Pool`
  без сужения по драйверу) и намеренно неверные входы негативных тестов (там нужен
  `as never`, а не исправление). Рантайм не затронут: сценарии гоняет `db-ported.test.ts`.
  Отложено в этот чек-лист, потому что это код `lib/db`.

### Проверка «вместе не создают ли нового бага» (ход 42)

- **Сейчас — нет.** Хук приложения не передаёт `paths`, поэтому код F43 в приложении не
  исполняется. Пропущенная граница у `/api/db-posts` в хуке даёт лишь то, что
  несуществующий адрес вроде `/api/db-postsX` поднимает PGlite и получает контекст БД перед
  ответом 404. Данных он не открывает: маршрута нет.
- **Связь есть при исправлении.** Если исправить C1 (перейти на `paths`) без F43, ошибка
  F43 станет живой: `/db-demoX` получит контекст БД. Поэтому эти пункты чинятся одним
  коммитом, F43 первым.
- **Разница в поведении, которую принесёт C1.** Вне `paths` `dbHandle` всё равно ставит
  `locals.dbCtx` с гостем (`createRequestContext(event, guest)`), а нынешний хук не ставит
  ничего. Это нужно учесть при исправлении: либо так и задумано (гость везде), либо `paths`
  должен пропускать запрос целиком.
