# Защита сетевых вызовов браузера от подмены — план (ОТЛОЖЕН)

Статус: **отложен решением владельца (ход 251)**. Вердикт владельца: «не уверен, что есть
защита толковая. Банковские приложения так взламывают, а там ребята умнее чем мы.
Делать сложнее, чем сейчас — стрельба себе в ноги». План открывается только по слову
владельца. В текущую работу модуля пользователя не входит; на каркас и `#lib/fetch`
ничего из этого не навешиваем.

## Цель (если план когда-нибудь откроют)

Подмена `window.fetch` и других функций страницы не должна перенаправлять вызовы
приложения — в этом месте вызов должен просто ломаться (падать с ошибкой), а не
работать на подменившего.

## Уровень 1. Захват ссылки на fetch при старте приложения

Модуль при первом исполнении кода берёт ссылку на настоящий `fetch` и замораживает её;
все сетевые вызовы приложения идут только через эту ссылку. Подмена глобала после
старта на вызовы приложения не влияет. Проверка целостности — у настоящего `fetch`
текст функции содержит `[native code]`.

Точка в проекте уже есть: `#lib/fetch` — единственный разрешённый вход сетевых вызовов.

Что исследовать при открытии плана:
- момент захвата: бандл SvelteKit исполняется частями — скрипт, вставленный на
  страницу раньше нашего кода, успеет подменить `fetch` ДО захвата; как гарантировать
  порядок;
- проверка `[native code]` подделывается: обёртка может притвориться нативной
  функцией; насколько эта проверка вообще честная;
- достаточно ли одной точки `#lib/fetch` (не остаётся ли вызовов мимо неё).

## Уровень 2. Service Worker владеет сетью

Страница не зовёт сеть сама: она передаёт запрос в Service Worker (сообщение),
а Worker вызывает сеть своим собственным, захваченным `fetch`. Подмена `fetch` на
странице в цепочке не участвует вообще.

Что исследовать при открытии плана:
- совместимость с SvelteKit: Worker кладётся в `static/`, сборка и адаптер
  (adapter-auto) — проверить, что не ломается;
- первое посещение: Worker ещё не установлен — окно без защиты; как считаем этот
  случай;
- сбой или удаление Worker = приложение отказывает целиком (это свойство и есть
  цель «подмена ломает вызов», но оно же — риск доступности);
- конфликт с живым обновлением и опросами проекта (NDJSON, курсоры);
- известная атака: если чужой скрипт смог исполниться И положить файл на наш домен,
  он регистрирует свой Worker — становится постоянной подменой, которую не убрать
  без чистки хранилища. Средства: заголовок CSP на ответ Worker-скрипта, Trusted
  Types на регистрацию (адрес скрипта — охраняемое место по спецификации Trusted Types).

## Уровень 3. Не дать подмене запуститься: CSP и Trusted Types

**SvelteKit уже делает часть за нас (проверено по докам svelte.dev, ход 251):**
настройка `kit.csp` — режимы `'hash' | 'nonce' | 'auto'`. SvelteKit сам вычисляет
хэши или одноразовые ключи для всех встроенных скриптов и стилей, которые сам
генерирует, и подмешивает их в политику; для своих скриптов в `app.html` есть
плейсхолдер `%sveltekit.nonce%`; дополнительные директивы задаются в той же
настройке; особые случаи — через хук `handle`. То есть базовый строгий CSP —
включается конфигурацией, чужой модуль не нужен.

Чего SvelteKit не делает сам:
- Trusted Types (`require-trusted-types-for`) — добавлять руками через `handle`;
  совместимость Svelte и приложения не проверена (Svelte в основных путях рендерит
  без `innerHTML`, но это надо проверять на нашем коде);
- директивы для сторонних скриптов — руками.

Известные препятствия именно нашего проекта (почему «может поломать многое» —
это опасение подтверждается):
- переходы Svelte создают встроенные `<style>`: доки Kit прямо предупреждают — либо
  не задавать `style-src`, либо ослаблять `'unsafe-inline'`;
- UnoCSS: как именно вставляет стили — проверить;
- разбор несовместимостей спецификации и реализации CSP: issue sveltejs/kit#15220.

Порядок безопасного внедрения (если когда-нибудь): сначала `reportOnly` (только
отчёты, ничего не блокируется) на неделю, разбор отчётов, потом включение блокировки.

## Готовые модули

- CSP — встроен в SvelteKit (см. уровень 3), сторонний не нужен.
- Захват `fetch` — десяток строк, модуль не нужен.
- Канал через Service Worker — готового не нашли при беглом поиске хода 251;
  искать отдельно при открытии плана (Workbox и похожие решают другие задачи).

## Критерий возврата к плану

Требование третьей стороны (внешний аудит безопасности, крупный заказчик) или
инцидент. Без такого требования сложность не оправдана — вердикт владельца.
