# lib/image — конвейер картинок (план, ход 261; код — после «го»)

## Задача (слова владельца)

Манипулировать изображением, самому выбирать конечный формат и алгоритм (энкодер), резать
палитру независимо от формата и алгоритма. Сжатие до заданного веса — НЕ задача слоя:
слой даёт возможность, перебор параметров и сверку с рамкой веса делает владелец
(цикл: сначала только качество 99→80; если тяжело — режем цвета и снова качество 99→80;
«рано или поздно найдём»).

## Цепочка (формулировка владельца)

```
изображение → манипулирование (параметры image-q) → кодирование (формат, опции кодека)
подбор:     изображение → подбор (формат, опции)
```

Последняя ступень — кодирование (энкод): на выходе Blob заявленного формата.

## API (черновик к обсуждению при имплементации)

```ts
const p = open(blob)                                  // декод + EXIF-поворот
  .frame({ width: 200, height: 200, fit: 'cover' })   // геометрия: cover — накрыть и обрезать
                                                      // по центру, contain — вписать целиком
  .quantize({ colors: 64, dithering: 0.5 })           // манипулирование: image-q (ленивый чанк)
  .encode('image/png', { quality: 0.9 })              // → Promise<Blob>

const hit = await open(blob)                          // подбор: тот же конвейер, но перебор
  .frame({ width: edge, height: edge })
  .fit({ formats: ['image/jpeg', 'image/png'], quality: [0.8, 0.99], colors: [16, 256] },
       (blob) => blob.size + PREFIX <= maxBytes)      // рамку веса знает только владелец
// hit: { blob, params: { format, quality, colors? } } | null
```

- Энкодеры — таблица «формат → кодек»: новый алгоритм = строка таблицы, код потребителя
  не меняется. Начало: `image/jpeg` → @jsquash/jpeg (MozJPEG, уже в проекте),
  `image/png` → @jsquash/png (lossless; палитру держит image-q). Смена jpg↔png — аргумент.
- Подбор — не равноправный перебор: размерности ранжированы «визуальной ценой» (наблюдение
  владельца, ход 261): качество (вглубь, пол задаёт вызывающий) → канал — grayscale выбрасывает
  цветовые плоскости целиком и фаворит для почти-монохромных кадров (@jsquash/jpeg: `color_space:
  GRAYSCALE|RGB|YCbCr`), opt-in — потеря цвета решает владелец → палитра (16 цветов — полосатость
  и дизеринг, последняя надежда). При кадре — дешёвая проба насыщенности: почти-монохромный и
  grayscale разрешён — пробовать его раньше палитры. Бинарный поиск по монотонности (выше
  качество/больше цветов — тяжелее); кривую цвета искать без дизеринга (шум палитры ломает
  монотонность PNG). Порядок форматов — порядок предпочтения.
- `fit` ничего не знает про data:-URL и сервер: рамку (`fits`) даёт потребитель.

## Зависимости

- `+ image-q` — квантование + дизеринг: ~19 КиБ gzip JS (замер tarball, ход 261), лениво.
- `+ @jsquash/png` — JS ~3 КиБ gzip, wasm-ассет ~181 КиБ грузится при первом использовании
  (ассет, не бюджет JS).
- `@jsquash/jpeg` — уже стоит.
- `compressorjs` — из package.json уходит (миграция потребителей ниже).

## Потребители

- `content/user/avatar.ts` — `open(file).frame(edge×edge)` → `fit(..., вся data:-строка ≤ maxBytes)`
  (заодно лечит «впритык»: сервер считает префикс `data:image/jpeg;base64,`). Настройки — конфиг
  (`avatarEdge`, `avatarMaxBytes`, `avatarFormats`); серверный белый список расширяется вместе с форматом.
- `ui/file-input/FileInput.svelte` (миниатюры превью) — `open(file).frame(80×80)` →
  `encode('image/jpeg', { quality: 0.8 })` → objectURL; не вышло — objectURL оригинала (как решено, ход 260).
