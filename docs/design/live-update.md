## 2. Принципы

- **Отметки даёт база**, не часы клиента **(владелец)**. Каждый ответ опроса несёт следующую
  отметку.
- **Спрашивать только то, что у пользователя перед глазами или рядом** **(владелец)**:
  - новые — только когда окно у края свежих данных;
  - изменённые — только в пределах загруженного, и не для всего загруженного, а для порции
    в поле зрения и соседних;
  - вдали от края новых не спрашиваем вовсе (пользователь на 20-й странице на первую,
    скорее всего, не вернётся).
- **Возможности таблицы решают, что спрашивать** **(владелец)**: нет `updated_at` — только
  новые; нет `deleted_at` — удаления не видны до перезагрузки.
- **Запись, выпавшая из фильтра после изменения, не помечается** **(владелец)**: она просто не
  придёт как изменённая, у клиента останется старая версия до перезагрузки. Для обычного сайта
  этого достаточно.
- **Чтение удалённых — только админ** **(владелец)**. Опрос отдаёт лишь `id` удалённой строки,
  без содержимого, — чтобы клиент её убрал.
- Ядро пагинатора без таймеров (как сейчас); задержки и интервалы — в UI-слое.

## 3. Режим страниц: срез на момент

Проблема: номер страницы — это смещение. Пришли 10 записей при размере 5 — `?page=3` после
перезагрузки покажет то, что было на первой.

**Решение (владелец):** ключ среза в адресе. Имя — §9, вопрос 1 (`page.asof` или `page.start`);
ниже — `asof`.

- **Значение:** `created_at` и `id` самой свежей строки выдачи на момент первой загрузки
  (то же, что сегодняшняя отметка опроса). Все страницы читаются с условием «не новее среза»
  по паре `(created_at, id)`; `count` — под тем же условием, поэтому число страниц стабильно.
- **Откуда:** первая загрузка без ключа → сервер кладёт `asof` в `extra` ответа (так же
  сегодня приезжает `after`) → ядро пишет его в состояние, адрес и ссылки страниц. Без JS
  ссылки из SSR несут тот же ключ.
- **Новые:** опрос «новее среза» идёт **только на первой странице**. Результат — пилюля
  «N новых». Клик — сброс пагинатора (`reset`): новый срез, первая страница **(владелец)**.
  Переход на страницу 1 без сброса показывает её относительно старого среза — пилюля остаётся.
- **После перезагрузки со старым срезом** на первой странице пилюля появляется после первого
  ответа опроса: это и есть путь «до начала».
- **На страницах дальше первой** новых не спрашиваем. Изменения — только для текущей страницы
  (§5.2).
- Жёсткое удаление по-прежнему сдвигает страницы на одну строку; с `deleted_at` (§6) — нет,
  если удалённые строки остаются в срезе как «удалено» — §9, вопрос 5.

## 4. Режим курсора: порции со своими ключами

У курсора нет номеров страниц: «страница» — порция, загруженная от закладки.

**Решение (владелец):**

1. **Каждая порция — страница со своим ключом.** Ключ — закладка, от которой порция началась.
2. **В адресе — ключ порции, которую человек читает** (видимую порцию ядро уже знает:
   `reportAnchor`). Не указатель следующего шага, как сейчас.
3. **Новые строки из опроса — отдельная порция со своим ключом** «новее верхней строки».
   Опрос отдаёт вместе со строками подписанную закладку партии.
4. **Перезагрузка** → «дай порцию от этого ключа», дальше обычными порциями. Читал только
   новые → срез начинается с нового сообщения и идёт нормальными размерами.
5. **Автообновление включено, только пока окно касается края** свежих данных: лента («новые
   сверху») — верх, чат («новые снизу») — низ. Срез после перезагрузки не у края → опроса
   новых нет, пока пользователь не догрузит до края **(владелец)**.

### Что нужно в `lib/db`

- **Обратное направление:** `api.cursor(ctx, { before })` — «строки новее закладки» (запрос
  в обратном порядке, ответ разворачивается). Ответ несёт обе закладки порции и признаки:
  `{ items, nextCursor, prevCursor, atEdge }`. `atEdge` — «новее этой порции ничего нет»
  (тот же запрос `LIMIT n+1` в сторону свежих).
- Удалённая строка закладку не ломает: в закладке значения, а не ссылка на строку; ближайшую
  находит индекс. `ctid` PostgreSQL как идентификатор не годится (меняется при UPDATE и
  VACUUM FULL); числовой `id` для этого не нужен.

### Что нужно в пагинаторе и демо

- `extra` курсора: ключ видимой порции вместо `after` следующего шага; закладки соседних
  порций — в состоянии порций, не в адресе.
- Догрузка к краю — `loadMore(-1)` (в ядре есть, со сдвигом прокрутки при вставке сверху).
- Размер порции новых — §9, вопрос 2.
- Чат-режим в `/db-demo` сейчас не сделан сознательно (`PLAN.md`, «Прочее»); механизм обязан
  не зависеть от стороны края, проверка — модульными тестами ядра и источником демо-пагинатора.

## 5. Опрос

Один запрос на тик; что в нём спрашивать, решает список по положению окна.

### 5.1 Новые

- Только у края (§3, §4).
- `created_at > отметка` под фильтром, не больше `DB_FRESH_LIMIT`. Больше — ответ «список
  сильно изменился» → пилюля «обновить» (сброс).

### 5.2 Изменённые — только если у таблицы есть `updated_at`

- **Границы:** строки между верхней и нижней строкой **видимой порции и соседних, по одной
  с каждой стороны** (в режиме страниц — текущая страница). Сервер читает только этот кусок:
  `updated_at > отметка и (ключ сортировки) между границами и фильтр`. Границы с клиента
  безопасны — только сужают выборку; права проверяются как обычно.
- **Дополнительный опрос при прокрутке (владелец):** порция вошла в поле зрения, а её
  последняя проверка старше текущей отметки → один запрос изменений для неё. Не чаще
  интервала опроса; задержка — в UI-слое (`live.svelte.ts`), ядро сообщает только смену
  видимой порции (`reportAnchor` / событие `page-changed`).
- Применение — `patchItems({ update })`. Если изменилось поле сортировки и строка уже не на
  своём месте — убрать из окна (`{ remove }`) и посчитать в пилюлю.
- **Порядок фиксации:** транзакция может завершиться позже, чем записала своё `updated_at`.
  Спрашивать с запасом (`> отметка − несколько секунд`) и отбрасывать повторы по
  `(id, updated_at)`.

### 5.3 Удалённые — только если у таблицы есть `deleted_at`

- В тех же границах, что 5.2: `deleted_at > отметка` → только `id`. Применение —
  `patchItems({ remove })`.
- Содержимое удалённых наружу не идёт; `readDeleted` — только у админа, админа пока нет →
  запрещено всем.

### 5.4 Вдали от края и без изменяемых полей

- Не у края и у таблицы нет `updated_at`/`deleted_at` → опроса нет вовсе.

### 5.5 Как остаётся

- `If-None-Match` → 304 без чтения базы, пауза на скрытой вкладке, backoff — без изменений.
- После долгой паузы один запрос со старой отметкой забирает всё накопившееся (удалённые
  видны, пока строка с `deleted_at` в базе).

## 6. Системные поля в `lib/db`

Берётся проект `ACL-DESIGN.md` §2 п. 4 без остального ACL **(владелец: «я просил поддержку
этих системных полей»)**:

- `timestamps: { createdAt?, updatedAt?, deletedAt? }` у ресурса — три независимых
  переключателя, имена колонок свои. Каждое поле `generated` + `immutable`: клиент не пишет,
  значение ставит база (`clock_timestamp()`), `updatedAt` — при каждом `update`.
- `deletedAt` включает `softDelete` и действие `restore`; чтение удалённых — `readDeleted`.
- **Признак ресурса для опроса:** какие вопросы ресурс поддерживает (новые — всегда,
  изменённые — есть `updatedAt`, удалённые — есть `deletedAt`). Признак выводится из
  `timestamps` автоматически, отдельной опции нет **(владелец, §9.4)**.
- Индексы: `(updated_at, id)` по живым строкам и `(deleted_at, id) WHERE deleted_at IS NOT NULL`
  создаёт схема из моделей (`defineSchema`). Частичный по живым, как прочие индексы ресурса с
  мягким удалением, для удалённых был бы пуст.
- Решено владельцем (2026-10-15): поля создаёт сама библиотека (значение — имя поля; объявить
  его ещё и в `fields` — ошибка); удалённые по умолчанию не видит и не восстанавливает никто,
  право — `deletedAt: { field, readDeleted }`; восстановление — метод `restore(ctx, id)` с
  необязательной политикой `policy.restore` (нет — как у `delete`); признак опроса —
  функция `liveCapabilities(resource)`.
- Демо: `src/content/posts.ts` получает `updatedAt` и `deletedAt`; форма удаления становится
  мягким удалением.

## 7. Время жизни указателя

Указатель ничего не держит на сервере, права проверяются на каждом запросе — 30 минут
защищают мало, а теряют ленту после простоя. Варианты (выбор — §9, вопрос 3):

- **а)** поднять `DB_CURSOR_TTL_SECONDS` по умолчанию (сутки или неделя);
- **б)** скользящее продление: просроченный, но подлинный указатель (подпись и `scope` верны)
  принимается в пределах максимального возраста, в ответе — новый;
- **в)** при отказе — продолжить с ближайшей строки по значениям последней показанной строки
  вместо «начните с первой страницы».

Выбрано **б** **(владелец, §9.3)**.

## 8. Шаги

Каждый шаг — свой коммит с зелёным gate и браузерными наборами.

0. **Сброс страницы при оживлении** (§1, находка 1) — **СДЕЛАНО.** `externalExtraDiff` в
   `paginate/pure.ts`: «ключа нет» = значение по умолчанию (умолчания URL-адаптер отдаёт хосту в
   `searchSpec.extraDefaults`). Правило «`''` = ключа нет» не понадобилось. Попутно вскрылась
   скрытая опора курсора на этот сброс: указатель следующего шага есть в снимке сервера, но не в
   адресе, и первое сравнение снимало его — первый клик «дальше» уходил без указателя. Поэтому
   при первом сравнении после оживления отсутствие позиционного ключа в адресе его не снимает.
   Проверки: модульные (`paginate.test.ts`), браузерная «прямая загрузка `?page=2` держится после
   гидрации, без запроса» в `db-demo-browser.check.mjs`.
1. **`lib/db`: `timestamps`** (§6) — **СДЕЛАНО.** `timestamps`, `restore`, `policy.restore`,
   `liveCapabilities`; 8 групп в `db-rules.test.ts`, README/PORTING, счётчики `db-docs`. Модель
   `posts` переведена: удаление в демо мягкое. Переход старой базы проверен на сборке: колонки
   добавляются сами (`add_column`, уровень `auto`), `updated_at` у старых строк = время перехода.
2. **`lib/db`: курсор в обе стороны** (§4) — `before`, `prevCursor`, `atEdge`; тесты: удалённая
   строка-закладка, одинаковое время, фильтр.
3. **Срез режима страниц** (§3) — источник, эндпоинт, ссылки; браузер: пришли записи →
   `?page=3` после перезагрузки показывает те же строки; пилюля только на первой; клик — сброс.
4. **Порции курсора с ключами** (§4) — адрес = видимая порция; порция новых; опрос только
   у края; браузер: перезагрузка в середине → тот же срез, опроса нет до догрузки к краю.
5. **Опрос изменённых и удалённых** (§5.2–5.4) — границы, опрос при прокрутке, запас по
   времени; HTTP-проба границ; браузер: правка видимой строки приходит, правка за пределами
   загруженного — нет.
6. **Время жизни указателя** (§7).
7. **Документы:** README `lib/db`, `paginate`, `db-demo`; закрыть «Открыто — Г» в `PLAN.md`,
   пометить Р6/T8.2 в `LIVE-APPEND.md`; статус этого файла.

## 9. Вопросы — закрыты владельцем (2026-10-15)

1. **Имя ключа среза:** `page.asof`.
2. **Порция новых в курсоре:** закрывается по достижении размера порции, дальше — следующая.
3. **Время жизни указателя:** б — скользящее продление в пределах максимального возраста.
4. **Признак ресурса для опроса:** выводится из `timestamps` автоматически.
5. **Удалённые в срезе страниц:** строка исчезает, страницы сдвигаются на одну.
