# Состояние задачи («лоадер»): где оно возникает, кто его отдаёт, кто показывает

Статус: **ИССЛЕДОВАНИЕ, не реализовано** (ход 129, запросы владельца 130–135).
Решения владельца, на которых стоит документ:

- Состояние приходит **в ответе на сам запрос**. Опросов и отдельной точки доступа нет.
- Строки состояния пишутся только тогда, когда запрос реально ждёт долгую операцию. Если ждать нечего, ответ байт в байт как сейчас.
- Переходы через загрузчики SvelteKit (`load` → `__data.json`) — вариант **(а)**: полоска без числа.
- Процент бывает двух видов:
  - **байты** — честный процент, `Content-Length`;
  - **шаги** — индикатор готовности: `done/total` этапов процесса, а не время до конца.
- Если долгое ожидание у библиотеки (lib), то **lib сама отдаёт состояние**. Наш лоадер в lib не подключается. Формат для потребителя один.
- Все ссылки и кнопки показывают состояние через один глобальный лоадер на клиенте: у кнопки — значок и процент, сверху — полоска.

## 1. Единый формат (предложение, требует согласия: публичный API)

```ts
type TaskState =
  | { status: 'idle' }
  | { status: 'pending'; scope: 'local' | 'global'; label?: string; progress?: TaskProgress }
  | { status: 'error'; message: string }

type TaskProgress =
  | { kind: 'bytes'; loaded: number; total: number }                 // честный процент
  | { kind: 'steps'; done: number; total: number; step?: string }    // готовность по этапам
```

**Показ:**
- `pending` без `progress` — значок-спиннер;
- с `progress` — спиннер и рядом `43%`;
- для `steps` процент считается как `done/total`, название шага уходит в `title` и `aria-live`;
- `scope: 'global'` дополнительно зажигает полоску сверху;
- `local` зажигает полоску, только если задача дольше примерно 150 мс.

**Строки в ответе** (NDJSON, только когда запрос ждёт):

```
{"task":{"status":"pending","scope":"global","label":"Запуск базы","progress":{"kind":"steps","done":1,"total":4,"step":"Подключение"}}}
{"task":{"status":"pending","scope":"global","label":"Запуск базы","progress":{"kind":"steps","done":4,"total":4}}}
{"result":{ …обычный ответ… }}
```

## 5. Нагрузка

- Число запросов не меняется: один на нажатие.
- Строки пишутся по событию «шаг завершён», без таймеров. Нужен список ждущих у общего промиса; запрос ушёл — убран.
- Длительность запроса прежняя: он и так ждёт операцию.
- Если ждать нечего, ответ байт в байт прежний.
- Клиент: примерно 1,5–2 KiB gzip (`readTaskStream`, глобальный лоадер, полоска, `Link`, `task` у `Button`). Лимит JS 231,1/232 придётся поднять.
