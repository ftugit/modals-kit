## B. Перехват полей (lib/form) — дизайн закрыт

- Объявление: функция у конкретного поля при привязке (клиент):
  `bind(forms, desc, { takeovers: { avatar: (f) => … } })`. Сервер
  импортирует только описание формы; поля и перехваты рождаются у
  клиента. Умолчание проекта при повторе — `forms.config`.
- Ручка — сам `FieldView`: значение и ошибки уже есть
  (`f.value`/`f.onInput`/`f.errors`). lib/form добавляет ровно два
  писателя: `setError` (ошибка операции поля: `origin: 'external'`,
  живёт по pins — видна до смены значения, собственная проверка
  сильнее, блокирует клиентскую отправку; сервер не воспроизводит)
  и удержание отправки, пока перехватчик готовит значение.
- Замена видимого компонента — возвратом фабрики
  `{ view, base, dispose? }`: база сверяется с примитивом, который
  resolve дал этому полю (обобщение существующего `Field instead`:
  там база захардкожена на Input, реестр — руками в Field.svelte;
  здесь база приходит в возврате явно). Несовпадение — прежний
  компонент + dev-предупреждение. Ошибки при замене остаются на
  месте: их рисует `FieldShell` вокруг любого компонента поля.
- Правда отправки — DOM (bind строит FormData из элемента формы при
  отправке, оценке, проверках и pins). Запись значения
  перехватчиком — пара: значение в именованный носитель из
  `f.attrs` (для файла — DataTransfer в carrier) + `f.onInput(...)`.
  Внутренние инпуты перехватчика имени не имеют и существуют только
  после оживления; до оживления — штатный компонент поля (noJS
  честный). Blob от lib: `new File([blob], 'avatar.jpg', {type})`.
- Гард: `setError` вне кита полей и перехватчиков запрещён.
- Потребитель №1 — фото (бывший R2): staging без имени → lib/image
  готовит JPEG → File в carrier + onInput; ошибка подготовки —
  setError; валидация содержимого — check из R1.

## A. Шаги — целевая картина

Одна система шагов: обычный хост `useSteps`. Шаг объявляется заранее
списком и переключается тремя путями: ссылкой (`StepLink`), кнопкой
(submit экшена шага) и СОБЫТИЕМ (результат экшена, функция) — канала
события сейчас нет, его и добавляем. Форма со шагами — нарезка полей
одной формы по текущему шагу (поля шага живут в разметке шага);
валидация шага — `subset` экшена в описании (ядро lib/form умеет).
Шаг может быть: срезом одной формы; отдельным компонентом со своей
формой; чистым UI без формы.

`formSteps`/`FormSteps` («паразит») — под снос после перевода демо
/steps на обычный хост. Основания (сверено с кодом):

1. Потребитель один — собственное демо; рабочие потребители
   (авторизация, /fields) живут на обычном хосте.
2. Две противоположные модели скрытых значений в одном проекте:
   нарезка — поля скрытого шага нет в DOM, значение в отправку не
   попадает; паразит — все шаги в DOM под CSS, всё едет в каждый
   POST. Остаётся одна модель — нарезка.
3. Событийного перехода (главный реальный сценарий) нет ни в хосте,
   ни в паразите — все пишут stepOf руками; зато построен «разбор»
   (закрепление шагов с ошибками, details-свёртки) ради wizard-UX,
   которого в продукте нет. Канал события строим, разбор не несём.
4. Карта «поле → шаг» у паразита троится: subset экшена + список
   шагов + сниппеты (ключ шага = id экшена по конвенции). В нарезке
   карта одна — разметка.
5. Хост при этом перегружен адресной механикой (3 режима, бронь
   ключей, замок, аргументы), а `current` в local/hybrid — только
   начальное значение; `filled` каждый потребитель считает руками
   (в виджете — константы). Служебные состояния вне списка
   невидимы для `items`.

Декомпозиция авторизации по целевой картине: одна форма входа
(entry/register/restore, без полей профиля); профиль — отдельный
компонент со своей формой (nickname + photo, свой обработчик —
серверная часть R3); blocked/restrictions — UI-шаги без формы
(restrictions «Принято» — программная отправка конверта auth,
механизм `authEnvelope*` есть). «Пропустить профиль» перестаёт быть
отправкой — просто смена шага/закрытие. Без JS шаг после POST
по-прежнему определяет сервер (load по сессии); deep-link на шаг
профиля без сессии сворачивается на entry.

## Порядок работ и гейты

1. lib/form: перехват в bind (setError, hold, возврат view+base) —
   контракт-тесты жизненного цикла ошибки (установка → показ →
   блокировка отправки → смена значения → снятие), гард на setError.
2. Шаги: канал события → шаг; демо /steps переведено на хост +
   нарезку + subset; паразит удалён; README шагов переписан под
   одну систему.
3. Декомпозиция AuthWidget; форма профиля с фото-перехватом;
   эмуляции авторизации (54 теста) переживают декомпозицию.
4. Сервер формы профиля (R3), далее R4 по прежнему плану.
Документация: README lib/form (перехват), README шагов, ревизия
объёма R2/R3 в `image-transfer.md`. Вес: перехватчики — ленивые
чанки владельцев полей (как `photo.ts` в R1), ядро bind не раздувать.
