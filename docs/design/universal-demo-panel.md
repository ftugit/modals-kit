## Вес: `bind` тянет весь `lib/form`

`lib/form/svelte/bind.svelte.ts` статически импортирует отправку, асинхронные
проверки, конверт, редактор схемы. Сборщик не может выбросить неиспользуемое, поэтому
любая форма — даже панель из восьми выпадающих списков без отправки — приносит весь
`lib/form`.

Замер (ход 10, sourcemap production-сборки, байты каждого исходника в чанках раздела):

- `/form`, `/modals`, `/paginator`, `/db-demo` — **у всех один и тот же полный
  `lib/form`: 46.9 KiB минифицированного кода** (чанк ≈ 18.6 KiB gzip вместе с
  виджетами настроек).
- По файлам (KiB, минифицировано): `bind` 7.3 · `validators` 6.5 · `builtins` 4.7 ·
  `describe` 4.0 · `messages` 2.9 · `editor` 2.9 · `submit` 2.7 · `async` 2.1 ·
  `spec` 1.9 · `strength` 1.5 · `validate` 1.4 · `policy` 1.2 · `envelope` 1.2 ·
  остальное < 1.
- Панели без отправки не нужны `submit`, `async`, `envelope`, `editor`, `spec`,
  `strength` — ≈ 12 KiB минифицированного кода, **оценка 3–5 KiB gzip** (пропорция
  по степени сжатия чанка, не замер).

Ожидаемый эффект по разделам (оценка):

| Раздел | Эффект |
|---|---|
| `/modals` | −3…5 KiB; бюджет маршрута снова с запасом |
| `/paginator` | панели, фильтры и поиск, вероятно, столько же; **проверить**, не использует ли «Применить» фильтров отправку |
| `/db-demo` | меньше: формы создания и удаления отправляют, `submit` остаётся |
| `/form` | без изменений: странице нужно всё |

Поведение для пользователя не меняется: без JS — та же нативная отправка, с JS код
отправки приезжает только туда, где форма действительно отправляет.

Связь с бюджетом: `/modals` превысил лимит на 0.1 KiB в ходе 10 (F23 +0.4, F12 +0.1;
148.6 > 148.5 KiB) именно потому, что каждая правка `lib/form` утяжеляет страницу модалок.

## Направление решения (черновик, не утверждено)

Две задачи сходятся в одну:

1. **Один компонент панели** `schema + sink`: схема полей (как `SettingsField[]`) и
   приёмник значений — хранилище пагинатора, `modals.configure`, состояние страницы.
   `PaginatorSettings` становится частным случаем (приёмник — пагинатор, гаты —
   возможности источника); `/modals` и `/form` подключают тот же компонент.
2. **Лёгкий контур `bind`**: поля, значения, живая запись — без отправки. Отправка,
   асинхронные проверки и конверт подключаются только формам, которые их объявили
   (отдельная точка входа или ленивая подгрузка). Затрагивает три бинда
   (svelte/react/solid — C9) и публичный API `lib/form/svelte`.

Открытые вопросы к владельцу (до начала работ):

- приёмник значений — проп-функция или адаптер (как у пагинатора)?
- нужна ли панели запись в адрес вне пагинатора (`/form`, `/modals`)?
- `SourcesPanel` — переводить на общий компонент (инвариант «последний источник не
  снять» требует динамических опций)?
- лёгкий контур — отдельный экспорт (`bindFields`?) или ленивые части внутри `bind`?

## Что не делать до утверждения

- не трогать `bind` ради бюджета;
- не переносить панели по частям: перенос имеет смысл только на готовый общий компонент.
