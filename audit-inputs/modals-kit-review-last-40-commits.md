## 2. Пользовательский баг: поиск demo без JavaScript возвращает 422

Воспроизведение на `/paginator` с отключённым JS:

1. Ввести `abc` в поиск.
2. Нажать «Найти».
3. Получить **HTTP 422**.
4. Поле очищается, внятной ошибки пользователю нет.

До отправки SSR-разметка содержит:

```text
name="page_param" value=""
name="from"       value=""
```

Причина — `CatalogDemo.svelte:485–492` использует старый вызов `SearchBar`, а `Listing.svelte:287–294` уже использует новый контракт и передаёт оба параметра.

Это одновременно:

- реальный функциональный баг;
- рассинхронизация ядра и пакета `demo`;
- пример двух подходов к одному действию в разных потребителях.

## 3. Блокер: `npm test` падает на собственном source-schema guard

## 5. «Костыли»: параллельные реализации одинакового поведения

### 5.1. Два реестра блоков фильтров

Есть две похожие реализации:

- `filter-blocks.svelte.ts` — контекстная;
- `filter-registry.svelte.ts` — глобальная по имени списка.

Обе хранят:

- `blocks`;
- `openKey`;
- `slot`;
- `claim`;
- `release`;
- `reclaim`.

`FilterBlock.svelte` постоянно разветвляется:

```ts
if (panel) ...
else if (listName) ...
```

При этом поведение уже различается. Например:

- контекстный `claim` отклоняет любой существующий блок;
- глобальный разрешает замену, если старый DOM-узел отсоединён.

Это именно параллельная подсистема вместо расширения существующей. Лучше иметь один store с областью видимости и адаптер для форм вне `Listing`.

### 5.2. Два разных механизма привязки портированных полей к форме

Одинаковая задача реализована отдельно в:

- `PopupSteps.svelte:101–139`;
- `FilterBlock.svelte:51–84`.

Обе реализации:

- ищут ближайшую `<form>`;
- генерируют `id`;
- выставляют `form` контролам;
- следят за DOM через `MutationObserver`.

Но одна дополнительно использует `requestAnimationFrame`, другая удаляет атрибуты при cleanup, а генерация идентификаторов различается. Это хороший кандидат на общий attachment/helper, а не на третью копию при следующем popup.

### 5.3. Положительный контраст

Сам `Floating` как раз является удачным шагом в обратную сторону: `Select`, меню, фильтры и шаги начали использовать общий цикл open/update/close. Проблема в том, что унификация проведена **не до конца и demo с тестами за ней не догнали**.
