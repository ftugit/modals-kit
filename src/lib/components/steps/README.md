# Шаги — универсальный хост (`useSteps` / `Steps`)

Шаг — состояние страницы, которое видит пользователь как «место в процессе». Хост
единый для всех потребителей и НЕ знает ни про формы, ни про содержимое: нарезать
на шаги можно что угодно.

## Два представления, один движок

- **Срезы одной формы** (`/fields`): форма одна, шаги показывают свои поля —
  перенос поля между шагами = переставить, где оно рендерится; валидация и
  отправка общие (авторизация живёт так же: одна форма `authForm`, шаги
  различает интент).
- **Произвольное содержимое** (`/steps` — демо): шаги показывают любые
  компоненты/тексты; хост даёт адрес, бронь ключа, замок полёта и навигацию.

## Режимы (`mode`)

| Режим | Где состояние | Когда |
|---|---|---|
| `url` (умолчание) | адрес (`?step=…`), истина — данные загрузки | классический wizard: ссылки, deep-link, обновление |
| `local` | внутри хоста, адрес не пишется | модалки: смена шага не должна касаться роутера |
| `hybrid` | внутри хоста + мягкая синхронизация адреса СВОИМ ключом брони | страницы, где смена шага с JS не должна дёргать сервер (load не вызывается), но обновление страницы и deep-link остаются верными |

В `local`/`hybrid` опция `current()` — только НАЧАЛЬНОЕ значение (данные
загрузки / deep-link); дальше состоянием ведает `set(key)`. Ответ экшена
приоритетнее адреса: его шаг тоже проводят через `set()` (в `hybrid` служебные
состояния, которых нет в списке шагов, адрес не получают — только локально).

## Как менять шаг БЕЗ участия сервера (паттерн)

Серверу не нужно знать о смене локального состояния:

```svelte
<script lang="ts">
  const steps = useSteps({ owner: 'мой-владелец', mode: 'hybrid', steps: DEFS, current: () => data.step ?? 'first' })

  async function открытьВторойШаг(): Promise<void> {
    // ...локальные побочные данные (например, ключ генерирует браузер)...
    steps.set('second') // в hybrid адрес обновится своим ключом (pushState, без load)
  }
</script>

<!-- href — fallback без JS: честный адрес, данные несёт load;
     с JS клик перехвачен — смену делает set() -->
{#each steps.items as it (it.key)}
  {#if !it.current}
    <a href={it.href} onclick={(e) => { e.preventDefault(); void открытьВторойШаг() }}>{it.label}</a>
  {/if}
{/each}
```

Правила:

1. **Адрес в `href` оставляем всегда** — это fallback без JS; перехват клика —
   прогрессивное улучшение, без скриптов всё продолжает работать.
2. **Серверные данные — только начальное состояние.** Не заводите зеркал
   «адрес → состояние» поверх хоста: в `local`/`hybrid` истина у `set()`,
   навигация синхронизирует одним эффектом (`data.step` → `steps.set`).
3. **Служебные состояния** (у авторизации — `profile`, `blocked`) — ключи вне
   списка шагов: `set()` их принимает, адреса они не получают.
4. **Чужие ключи адреса** (`?modal=`, `?page.…`) защищены бронью: адрес шага
   строится `nextSearch` и правит только свой ключ.

## Замок полёта и загрузка

- `lockKey` — ключ в `page.state`, который пишет форма на время отправки:
  ссылки видимые, но некликабельные (`aria-disabled`, guard, `set()` игнорирует).
- `items[].loading` — честный индикатор перехода именно на этот шаг (`linkTask`).

## Бронь ключей глобальна на приложение

`claimQuery` — реестр уровня приложения (SPA-сессия и серверный процесс): один
ключ адреса — один владелец, второй претендент получает ошибку брони. Поэтому
у каждой области свой ключ: `/fields` — `step`, авторизация — `stage`, демо
`/steps` — `ustep`/`lstep`/`hstep` (пример опции `key`). Выбирая ключ новому
потребителю, проверьте, что он никем не занят (ошибка брони назовёт владельца).

## Защита (dev, `console.warn` с рецептом)

- `set()` в режиме `url` — состояние там ведёт адрес; локальная смена нужна —
  берите `local`/`hybrid`.
- Дубликаты ключей в списке шагов — списком ведает владелец, каждый ключ один раз.
