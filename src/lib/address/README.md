# `#lib/address` — один писатель адреса на приложение

Адрес и состояние записи истории делят несколько владельцев: модалки (цепочка в
`?modal=` и `page.state`), пагинатор (`?page`, `?page.*`), флаги «мелких» записей
(мобильная панель). Каждый правит только свои ключи, но `goto` в SvelteKit 3
асинхронен: пока первая запись в полёте, `page.*` ещё старый, и вторая запись
затирала ключи первой (F41). Здесь все записи идут через одну очередь.

## Состав

| файл | что | фреймворк |
|---|---|---|
| `core.ts` | `createAddressWriter(deps)` — очередь записей: намерение синхронно, в полёте не больше одного коммита, обход истории побеждает, адрес страницы переживает закрытие слоя | нет |
| `layer-links.ts` | `createLayerLinks(storage)` — связки «слой → запись под ним» для системного «Назад» | нет |
| `svelte/watch.svelte.ts` | наблюдатель реактивного источника вне компонента (`$effect.root`) | Svelte |
| `sveltekit.ts` | адаптер к SvelteKit: единственный экземпляр писателя и функции ниже | SvelteKit |

## Адаптер SvelteKit

```ts
import { visibleAddress, writeAddress, goAddress, shallowFlag } from '#lib/address/sveltekit.js'

visibleAddress()                    // { url, state } — с учётом записей в полёте
await writeAddress((cur) => ({ url: cur.url, state: { ...cur.state, drawer: true } }), { replace: false })
goAddress(-1)                       // шаг назад ПОСЛЕ записей, стоящих в очереди
const drawer = shallowFlag('drawer') // drawer.on / drawer.push() — «Назад» закрывает, а не уводит
```

Ещё: `addressTraversing()` (идёт свой шаг по истории), `claimLayerKeys(test)` (ключи
слоя не переносятся на запись под ним), `visibleHref()`, `resolveHref(href)` (куда
ведёт ссылка от видимого адреса), `linkTask(href)` (адаптер `#lib/task`: идёт ли
переход именно на этот адрес).

Страницы, компоненты и демо-панели читают `visibleAddress()` и пишут через
`writeAddress`; прямые `page.url`, `goto` и `history.pushState` в `src/` запрещены
правилами `tooling/layer-guard.mjs` (сборка и тесты падают на нарушении).

Адаптеры чужих библиотек пишут адрес только отсюда: модалки —
`#lib/modals/cores/sveltekit.js`, пагинатор — `#lib/paginate/sveltekit/router.js`.
Свой писатель в любой из них означал бы вторую очередь и возврат F41.

## Другой роутер

Ядро не меняется; адаптер — функции `AddressWriterDeps`: обязательные `read` (адрес
и состояние фреймворка) и `commit` (записать), необязательные `hash` (текущий
`#якорь` адресной строки), `traverse` (шаг по истории) и `here` (адресная строка
целиком — в `popstate` она уже указывает на запись назначения). Затем адаптеры
модалок и пагинатора под тот же роутер.

## Бронь ключей и права (`keys`)

Писатель решает, КАК запись попадает в историю; `keys.ts` — ЧЕЙ ключ и ЧТО можно.
Потребитель бронирует ключи (`claimQuery('fields', 'step', 'step.*')`): точное имя
или семейство с точкой (`page.*` покрывает `page.size` и `page.filters.kind`).
Повторная бронь своего — не ошибка; чужое имя, чужое семейство и ключ под чужим
семейством — исключение при старте. Адаптер пагинатора бронирует при создании
(`paginate:<базовый ключ>`), ядро модалок — при первом `chainToSearch` (`modals`),
хук шагов — при создании (`useSteps`).

- `nextSearch(owner, from, patch, { drop })` — следующий search от видимого:
  правит только свой ключ, чужие остаются в значении и порядке. Ключ патча `x.*` —
  явная замена семейства одним значением (цепочка модалок); обычный `x` соседей
  не трогает (`page` рядом с `page.size`). `drop` — сброс своего семейства.
- `readQuery(from, name)` — чтение любого ключа, права не нужны; повторяющийся — массив.
- `carryQuery(owner, from, drop)` — перенос no-JS-формой: всё, кроме
  перечисленного; пустые значения не переносятся. Так адаптер пагинатора
  отдаёт `carryFields` (базу и относительные дропы добавляет сам).
- `checkKeys(owner, before, after)` — права правки: изменившиеся ключи обязаны
  быть своими. Писатель вызывает его на коммите, когда правка пришла с владельцем
  (`writeAddress(..., { owner })`) и путь не сменился: изменил чужой — запись
  отклоняется, мимо брони не пройти. Смена пути — переход на другую страницу,
  там своя бронь.

Свои потребители переведены: запись пагинатора (`mergeSearch`), перенос его формы
(`carryFields`), сброс и запись цепочки модалок (`chainToSearch`), шаги компонента
`Steps`. Честная проверка эквивалентности — `keys.test.ts` (сверка с настоящим
`chainToSearch` и `readPaginatorSearch`).

## Шаги страницы (`#lib/components/steps`)

Хук `useSteps({ owner, steps, current, lockKey })` над этой бронью: адрес шага
(`?step=…`) без потери чужих ключей, аргументы шага в своём семействе
(`step.fill.id` — читать `arg`, править `argHref`, как `modal.1.pack` у модалок),
замок полёта отправки — из состояния записи истории (`page.state`, пишет форма),
переход в полёте — `linkTask`. Компонент `Steps` рисует навигацию (ссылка —
заполненный шаг, текст — незаполненный, `aria-current="step"` — текущий) и
сниппет текущего шага; разметку шага пишет страница:

```svelte
<Steps host={steps} label="Шаги">
  {#snippet build()}…{/snippet}
  {#snippet fill()}…{/snippet}
</Steps>
```

## Ключ хранения

Связки слоёв живут в `sessionStorage` под `router:layer-links` — имя прежнее, чтобы
открытые вкладки не теряли связки после обновления.
