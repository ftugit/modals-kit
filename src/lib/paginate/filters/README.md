# paginate/filters — фильтры каталога

Схема фильтров источника превращается в форму `lib/form`, в правила проверки и в адрес
`?page.filters.<поле>[.<режим>]`. Модуль изоморфный, без фреймворка: один и тот же код работает
в серверной зоне схемы, в клиентской форме и в транспорте источника. О конкретном каталоге он
ничего не знает: источник приходит схемой (`CatalogFilterSchema`).

## 1. Схема

```ts
const schema: CatalogFilterSchema = {
  source: 'shikimori',          // ключ источника: по нему схема и помнится (§4)
  version: 1,
  builtAt: '2026-10-12T10:00:00.000Z',  // когда справочники прочитаны живьём
  fields: [
    { key: 'kind', label: 'Тип', type: 'select', options: [{ value: 'tv', label: 'TV' }] },
    { key: 'studios', label: 'Студии', type: 'multiselect', modes: ['and', 'not'],
      options: [{ value: '858', label: 'Wit Studio', count: 2 }, /* …все ~2000 */] },
    { key: 'score', label: 'Оценка', type: 'number', min: 1, max: 10, bounds: ['min'] },
  ],
  rules: [/* связки: что нельзя сочетать, с причиной для интерфейса */],
}
```

- `validateCatalogFilterSchema(input)` — проверяет схему. Невалидную схему нельзя отдавать
  клиенту, поэтому сборщик схемы источника прогоняет её через этот же валидатор.
- `compileCatalogFilterSchema(schema)` — превращает схему в описание формы `lib/form`: поля,
  правила (`minValue`/`maxValue`/`maxCount`, список допустимых значений) и связки (`disabledWhen`).
- `count` у опции — частота в популярной части каталога. Она задаёт порядок длинного списка (§2).

## 2. Длинные списки: с JS — все, без JS — топ-200

Решение владельца: «JS-форма за счёт поиска будет иметь все студии, no-JS — только
ограниченный список».

| | С JavaScript | Без JavaScript |
|---|---|---|
| Что в списке | все значения схемы (студий 1934) | первые 200 плюс всё уже выбранное |
| Как найти | поле поиска в списке ищет по всем, по подписи и значению | нативный `<select>` из серверной разметки, быстрый набор по началу имени |
| Пояснение под полем | нет | «Показаны не все значения: у источника их больше на N.» |
| Значение не из первых 200 | выбирается поиском | приходит адресом (ссылкой); показывается 201-м и выбранным |

Числа и функции:

| Что | Значение | Где |
|---|---|---|
| `CATALOG_FILTER_NOJS_OPTIONS` | 200 — показ без JS | `catalog-filter.ts` |
| `CATALOG_FILTER_OPTIONS_LIMIT` | 5000 — защита от гигантских форм, не размер показа | `catalog-filter.ts` |
| `capCatalogFilterOptions(schema)` | поле длиннее 200 упорядочивает по частоте, при равной — по подписи; поле длиннее 5000 обрезает (аварийно) и пишет `optionsTruncated` | `catalog-filter.ts` |
| `nativeLimit` у `Select` | сколько опций нативный `<select>` показывает до гидратации (0 — все) | `#lib/ui/primitives/Select.svelte` |

**Почему первые 200 — нужные.** Порядок задаёт сборщик схемы: частые первыми. Без частот в
первые 200 попали бы студии по алфавиту, и популярной «Wit Studio» там могло бы не оказаться.
Частоты Shikimori считаются по выборке из трёх страниц популярности (`shikimori-schema.ts`).

**Почему выбранное показывается сверх 200.** Нативный `<select>` отправляет только то, что в нём
есть. Если бы выбранной студии из хвоста не было среди опций, выбор пропал бы при следующей
отправке формы.

**Как это включить в своей форме:**

```svelte
<Select
  options={field.options}
  multiple
  config={{ nativeLimit: CATALOG_FILTER_NOJS_OPTIONS }}
/>
```

Порядок `options` и есть порядок показа: `nativeLimit` берёт первые N. Так сделано в
`#lib/ui/filters/CatalogFilterForm.svelte`, там же считается N для пояснения (тем же правилом:
первые N плюс выбранное).

**Вес.** Страница каталога (`/paginator?page.src=animes`, 2026-10-12): HTML 234 KiB
(43 KiB в gzip). В нём все 1934 студии для JS и по 200 в двух нативных списках («и» и «не»).
До изменения было 242 KiB: 1000 студий в данных и по 1000 в каждом нативном списке.

## 3. Проверка выбора

- Список допустимых значений строится по **всем** опциям поля
  (`catalogFilterOptionsAreComplete` → `true`). Студия из хвоста законна, чужой id отклоняется
  с кодом `oneOf`: и в браузере, и на сервере (`validateCatalogFilterValues`).
- Только у поля с `optionsTruncated` (справочник длиннее 5000) список неполный. Тогда
  проверяется синтаксис значения, а решает источник: он отвечает списком `dropped`.
- Окончательно выбор всегда проверяет сервер по своей текущей схеме. Поэтому старая схема в
  долгоживущей вкладке (§4) не опасна.

## 4. Схема в памяти вкладки

Решение владельца: схема, однажды пришедшая в браузер, хранится в оперативной памяти, пока
человек не ушёл с сайта или не перезагрузил страницу. Не localStorage: перезагрузка — законный
способ получить свежую схему.

```ts
import { catalogFilterSchemas } from '#lib/paginate/filters/index.js'

catalogFilterSchemas.remember(schema)           // под schema.source
catalogFilterSchemas.recall('shikimori')        // схема или null
```

- **Ключ — `source`:** так помнится схема любого источника, не одного.
- **На сервере память выключена:** переменная модуля там общая для всех запросов и
  пользователей, и схема одного запроса не должна стать ответом другому. `remember` на сервере
  ничего не делает, `recall` отвечает `null`.
- `createCatalogFilterSchemaMemory(enabled)` — своя память (тесты, другой жизненный цикл). По
  умолчанию `enabled = BROWSER` из `esm-env`.
- **Без JS** сохранить нечего: такому клиенту схема приходит с каждой страницей.

Как это использует демо каталога:

| Запрос | Схема с данными страницы | Откуда берёт браузер |
|---|---|---|
| Первый заход, перезагрузка, любой запрос без JS | да: нужна разметке без JS и гидратации | со страницы, сразу в память |
| Переход внутри сайта (`event.isDataRequest`) | нет | из памяти; если там пусто — один раз роутом (§5) |
| Смена фильтров, страниц, источника в панели | загрузка страницы не перезапускается | из памяти или роутом |

После перехода с каталога на главную и обратно данные страницы весят 10 KiB вместо 83 KiB.

## 5. Откуда браузер берёт схему

`GET /api/shikimori/filters` (`src/routes/api/shikimori/filters/+server.ts`) нужен, только когда
схемы нет ни в странице, ни в памяти:

- источник переключили в панели (адрес меняется без серверной загрузки);
- пришли на каталог переходом внутри сайта, а в памяти схемы ещё нет;
- сервер не собрал схему при отрисовке (Shikimori недоступен), и человек нажал «повторить».

Роут отвечает только страницам этого сайта: `Sec-Fetch-Site: same-origin`, иначе 403 без тела.
В dev по http запрос без заголовка пропускается (`sameOriginFetch` в
`src/lib/server/trusted-origins.ts`). От парсеров это не защищает, заголовок подделывается
одной строкой. Данные те же, что и в HTML страницы. В Shikimori роут не ходит: схема собирается
раз в 30 минут, одна сборка на всех.
