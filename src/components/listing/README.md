# `Listing`

Экран списка без модели. Контракт — [`docs/design/lists.md`](../../../docs/design/lists.md).

Доменный список регистрирует пагинатор, передаёт роут и строку. Оболочка держит шапку `Surface`, кнопку фильтров, поиск, ленту и ожидание. Поиск всегда над лентой. Зона sidebar передана и есть контекст страницы — форма в этой зоне с offset `999`, на любой ширине. На `max-lg` форма скрыта, кнопка в `controls` видна (`lg:hidden` на широком). Иначе только кнопка. Между поиском и лентой — чипы активных фильтров: те же ключи, что у счётчика. Подписи приходят от списка, из описания его формы. Чип снимает значение. Метка открывает нарезанный блок, только если форма смонтирована.

## Строку рисует хост, не оболочка

Оболочка не решает, из чего сделана строка. Сниппет `row` получает элемент и его
контекст:

```svelte
{#snippet row(item, ctx)}
  <img src={`/pic/${item.id}.png`} alt="" data-id={item.id} />
{/snippet}
```

`ctx` — `{ selected: boolean; page: number; index: number }`. Признак `selected`
считает сам хост: он передаёт `isSelected`, оболочка только вызывает её для
каждого id. Что означает «выбрано» и как это показывать — дело хоста, оболочка
про это не знает.

Ссылка не навязывается: нужна строка, которая куда-то ведёт, хост берёт готовый
`ListingRow` и сам передаёт ему адрес и поведение:

```svelte
{#snippet row(item, ctx)}
  <ListingRow attrs={attrsOf(item)} id={item.id} testId="session-row" selected={ctx.selected}>
    <SessionRow item={item} />
  </ListingRow>
{/snippet}
```

Атрибуты (`href`, `title`, attach-хук на клик) целиком приходят пропом `attrs` —
оболочка про адреса ничего не знает. Хост вправе не использовать `ListingRow`
вовсе: тогда `data-id`, `data-testid` и `data-selected` — его ответственность.

Отсюда же следует: чекбокс или любая другая кнопка внутри строки — это разметка
хоста, а не правка оболочки. Оболочка навязывает только див отступа вокруг
строки, и тот живёт в `Paginator` (`itemClass`).
