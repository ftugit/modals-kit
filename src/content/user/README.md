# `src/content/user` — модуль пользователя (seed-вход, отзыв токенов)

Статус: **каркас без реализации** (ход 251). Тела функций пустые — оценивается цепочка
вызова и покрытие правил статьи об отзыве JWT; правила реализации и источники —
`docs/design/auth-seed.md`. В routes не импортируется: подключение — gateway,
его включит `hooks.server.ts` при внедрении.

## Модуль, не библиотека

Папка в `src/content/` — модуль ПРИЛОЖЕНИЯ (как `posts.ts`, `shikimori-filters.ts`):
принадлежит домену «пользователь», а не переиспользуемому слою. Внутри одна папка
держит всё, что про юзера: БД-схему, поля форм, API, ошибки, gateway.

## Цепочка вызова (REST и POST одновременно)

```
POST /api/auth/login (+server.ts)   ─┐
                                      ├─> auth(event).login(args) ─> api.login(ports, args)
экшен ?/login (+page.server.ts)     ─┘

любой запрос: hooks.server.ts ─> auth(event).verify() ─> api.verify(ports)
                                └─> principalOf(result) ─> dbHandle({ principal })
                                    (замена DEMO_PRINCIPAL; гость — undefined)
```

Ядро не знает Request/Response/cookies: голые аргументы → голый факт `UserResult` (код+путь), перевод — инструкции `error.ts`.
Куки-носитель и HTTP-перевод — адаптер.

## Покрытие статьи об отзыве JWT

| Правило статьи | Где в ядре (модель владельца, ход 251) |
|---|---|
| 1. чёрный список на каждом запросе | ОТКЛОНЕНО владельцем: бан проверяет точка продления (см. `renew`); следствие — украденный access живёт до exp (≤ 15 мин), гайд признаёт эту цену |
| 2. короткий exp | `ACCESS_TTL_SEC` = 15 мин; access без jti — не хранится, не банится |
| 3. ротация секрета | `keys.secretOf(kid)`: старые принимаются, новый пишет |
| 4. версионирование | `ver` против `tokenVersion`; `logoutEverywhere` = инкремент |
| 5. выход и инвалидация | `logout`/`deleteIdentity`: токен продления блокируется до конца срока |
| 6. TRL | не выделен (минимум); стык — при надобности |
| 7. refresh | `renew`: одноразовый токен продления, блокируется при использовании; ПОГАШЕННАЯ запись хранится до конца срока — повтор = кража, гасим сессию целиком (уточнение статьи) |
| HttpOnly/Secure куки | `COOKIE_NAME`/`RENEWAL_COOKIE_NAME` + `CookiePort` |
| мониторинг аномалий | вне минимума; активность — TTL-ключ в `#lib/cache`, НЕ колонка auth |

## Приватность (§4 плана)

auth — технические поля (seed-псевдоним, времена, tokenVersion, блокировка,
резерв security); профиль — ровно никнейм и адрес аватара; ни email, ни имени,
ни IP, ни аналитических кук. Удаление (модель владельца): заявка → сессии мертвы
сразу, вход закрыт; через n дней (`DELETE_GRACE_DAYS`, решить владельцу)
исполнитель `sweepDeletions` удаляет профиль и стирает seed/security — строка
auth остаётся надгробием (id, времена). Активность — TTL-ключ в `#lib/cache`,
НЕ колонка auth (не двигает `updated_at`, меньше личных данных).
