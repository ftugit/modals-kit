# Симуляция: библиотеки `src/lib` под React Router

Проверка, что ядра библиотек не привязаны к SvelteKit, а их «хуки» повторяются в другом фреймворке.
Ничего из `src/` не копируется и не правится: тесты импортируют те же файлы, что и сайт.

Зависимости — только `react`, `react-dom`, `react-router`, `vitest`, `happy-dom` (и типы). Сборщика, сервера и
UI-кита нет: всё проверяется тестами в `happy-dom` с `createMemoryRouter`.

```sh
cd sim/react-router
npm install
npm test              # vitest run
npx tsc -p tsconfig.json   # строгая проверка типов: адаптеры + все файлы src/lib, которые они тянут
```

## Что лежит

| Файл | Строк | Что повторяет из Svelte-слоя |
|---|---|---|
| `src/address.ts` | 58 | `address/sveltekit.ts`: четыре зависимости писателя адреса + сигналы `external`/`applied` от роутера |
| `src/modals.tsx` | 200 | `modals/cores/sveltekit.ts` (движок) + данные из `ModalHost`/`state.svelte.ts`: провайдер, загрузчик, `useModals`, `useChain`, `useModal`, `useLoader` |
| `src/paginate.ts` | 160 | `paginate/sveltekit/router.ts` + `svelte/context.svelte.ts` + разбор адреса из `PaginatorHost` |
| `src/form.tsx` | 161 | малая часть `form/svelte/bind.svelte.ts`: поля из описания, локальная проверка, отправка, ошибки |

Не повторялось (это вёрстка, а не связка с роутером): анимации и геометрия окон, шторки, всплывающие окна,
прокрутка пагинатора, живая проверка формы на `blur`, асинхронные проверки, закреплённые серверные ошибки.

## Что проверяют тесты (15)

- **Модалки (7):** открытие пишет цепочку в адрес; закрытие идёт назад по истории и не трогает адрес страницы;
  «Назад» браузера закрывает, «Вперёд» открывает снова; прямая ссылка открывает окно; загрузчик работает только для
  верхнего окна; неизвестное имя из адреса показывается, а не пустое окно; две модалки — два шага истории.
- **Пагинатор (4):** старт со страницы из адреса; переход по списку пишет страницу в адрес и не теряет чужие ключи;
  переход извне двигает список; модалка и смена страницы в одном такте — оба ключа на месте.
- **Форма (4):** атрибуты ограничений в регистре React без предупреждений; неверная отправка остановлена локально,
  тексты — из словаря приложения (английские); верная доходит до настоящего серверного обработчика
  (`createFormHandler`, без сети); серверная ошибка попадает на своё поле.

## Что нашла симуляция

Пошаговый план переноса — [`docs/design/port-plan.md`](../../docs/design/port-plan.md). Коротко:

1. ~~Стартовая страница пагинатора читается из `window.location`, а не у подключённого роутера.~~ Исправлено в
   ядре (port-plan, шаг 1): URL-адаптер спрашивает роутер раньше `window`; обход в адаптере симуляции убран.
2. `writer.subscribe` сообщает только о своих записях. О чужом переходе сообщает роутер, и читатель адреса обязан
   слушать оба. Svelte получает это даром, React — нет. Это пробел в документации, не ошибка.
3. Ядро формы отдаёт имена атрибутов HTML (`maxlength`). React ругается
   (`Invalid DOM property 'maxlength'. Did you mean 'maxLength'?`), поэтому нужна таблица переименования.
4. `createLoader` (модалки) и `formRenderer` (форма) нужны любому адаптеру, но их нет в публичных `index.ts`.
5. Разбор адреса пагинатора и сборка строки запроса (`hrefOf`) пришлось скопировать из Svelte-файлов.
