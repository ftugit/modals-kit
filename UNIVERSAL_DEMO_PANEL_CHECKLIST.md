## Модель (из §3 промта — менять только по слову оператора)

disabled ≠ скрыто; причина в helper (отдельного узла нет; `helpProps()` отдаёт id при
`help` ИЛИ `reason`); значения выключенных полей не стираются и возвращаются со снятием
блокирующего; при JS-отправке набор собирает `lib/links` без значений выключенных полей
(дроп переезжает из патча `catalogFilterExtraPatch` в сборщик набора); валидатору отказы не
«добавляют» — он судит всем набором; без JS динамики нет; составитель текста один на helper
и ошибку; одинаковое значение в and/not гасит ЗНАЧЕНИЕ, выбор сохраняется, автоснятия нет;
живой режим (select: change; число: change/blur; текст: по завершению) без кнопки после
гидратации, до — нативная GET с кнопкой; невалидная комбинация не создаётся вовсе
(контрольная точка — создание комбинации: адрес + запрос источника, не запись в store);
адресную строку не переписывать (редиректы отклонены); невалидные входящие из URL не
«лечатся» — объяснение + deny-safe источника.

## Вопросы к оператору (накапливаются; решение — запись здесь + в этапе)

- **Q1. Единый крюк ошибок на всё приложение.** [проект предложен 2026-10-08, ждёт ок]
  **Решение: единого `onError` ВНУТРИ lib не делать** (инвертирует зависимость lib→app;
  глобальный синглтон течёт между запросами на SSR; ломает паритет монти). Lib держат
  СВОИ выходы ошибок (уже есть, проверено), а единственное место инжекта — мост на
  стороне приложения: `appErrors.report(источник, err)` → `$err` (прод — показать,
  dev — throw через `queueMicrotask`, чтобы не рвать emit-циклы) живёт только там.
  Уточнение (2026-10-08, на вопрос «через адаптер подключать?»): НЕТ. Хранилищный
  адаптер только БРОСАЕТ (persist) — про канал не знает, ловит и эмитит ядро;
  монти-адаптер (svelte/react/solid) — не владелец моста, максимум необязательный
  sugar (provider `onError`) над тем же каналом; `lib/form/url.ts` к ошибкам не
  прикасается. Проводка — одна точка на хосте: подписка на emitter инстанса (рядом с
  регистрацией в демо), конфиг `onErrors` форм, обёртка результатов `open()`.
  Инвентарь выходов: `form` — `onErrors?: ErrorHandler` в конфиге формы
  (`config.ts:83`, сервер `server.ts:262,325` через `applyHandler`, bind
  `bind.svelte.ts:104`) — трансформер, изоморфность документирована (`ctx.from`);
  в report оборачивается одна точка — конфиг. `paginate` — emitter `{type:'error',
  error, page, phase}` на инстанс (`types.ts:179`, core :139/:181/:302), монти уже
  подписуют через `emitter.on` (svelte `context.svelte.ts:195`, solid `adapter.tsx:724`)
  — подписка host на все инстансы; ЕДИНСТВЕННЫЙ refactoring — `safePersist` warn
  (`core.ts:26-34`) → событие эмиттера, outlet без канала сейчас. `modals` —
  результат-объект `{ok:false, error/reason}` у вызывающего (`loader.ts:22,178-198`)
  — данные, обёртка open() шлёт в report. `api/*` + fetch источника — текут через
  result формы и emitter пагинатора; HTTP 5xx страницы — корневой `+error.svelte`
  (файла нет — создать на этапе, UI «500 на проде»). bus/шину между lib не вводить.
  Механизм единого UI (2026-10-08, «как клиенту 500, а не-критичное в консоль»):
  В ПРИЛОЖЕНИИ один модуль `src/lib/app-errors.svelte.ts`: `report(err, {source,
  fatal})`; внутри вся развилка — DEV: `console.error` + `throw`; PROD+SSR критичное:
  `throw` → настоящий HTTP 500 через SvelteKit (`+error.svelte`, файла пока нет —
  создать); PROD+клиент критичное: `$state critical` → layout показывает ТОТ ЖЕ
  компонент 500 оверлеем (сменить HTTP-статус после загрузки страницы невозможно —
  потолок платформы, UI неотличим); не-критичное: `console.warn('[source]', err)`.
  Критичность решает МОСТ у хоста (lib про 500 не знают): init-фаза пагинатора/SSR
  загрузка — fatal; append-фаза, `persist-failed`, `empty-page`, modals `{ok:false}`,
  ошибки валидации форм — консоль/уведомление. Мосты: `emitter.on` у регистрации
  инстансов, `onErrors`-обёртка в конфиге форм, обёртка `open()`. Форма уже
  изоморфна (обработчик обязан — задокументировано), её `applyHandler` проходит и по
  action-пути на сервере: критичное там само бросится в 500.
  Переделать все приложение на один механизм инжекта ошибок: условно
  `onError(() => $err)` — ОДНО место, откуда ошибки берут UI-слой, сеть, формы,
  persist. Модель показа оператора: **прод — показать 500, dev — throw.** Что
  инвентаризировать при проектировании: `form` (`onErrors`/`ErrorHandler`,
  `display()` DEV-warn), `paginate` (emitter `error`, `safePersist` warn,
  reqId-отмены), корневой `+error` SvelteKit, эндпоинты `api/*` (jsonError),
  modals (`loader` `{ok:false,reason}`). Этап (предварительно — после 7, отдельным
  шагом; объём — весь app) и дизайн API: кто владелец $err, как адаптеры
  (react/solid) получают тот же канал, как DEV-throw не ломает гидратацию.
- **Q2. Приоритет хранилище ⇄ адрес (seed-политика).** [РЕШЕНО оператором
  2026-10-08, вето v2 поверх v1=(а) — «url на подхвате»: если url-хранилище передаёт
  данные (по объявленным ключам), другие хранилища не используются И НЕ пишутся; как
  только url очищен — работает подключенное хранилище; localStorage восстанавливает
  своё состояние (это его смысл), memory между перезапусками не переносится. Проверено
  по коду: реализуемо композицией адаптеров (фабрика поверх createLocalAdapter +
  url-канала), ядро не меняется; «данные в url» считать по объявленным ключам +
  deny-safe, иначе ?utm= перехватывает приоритет; модалочный прецедент — НЕ про
  маскирование: там источники сосуществуют разделением по `source` (build.ts
  readPerSource/order-merge), url ничей источник не гасит. Память у пагинатора ЕСТЬ:
  `storage.ts` `createMemoryStorage` + carrier по умолчанию в `createLocalAdapter`
  (:19), демо-экспозиция `demo-local-mem` — создавать нечего. Формы хранилищ не имеют
  полностью: в `lib/form` ни одного storage-потребления, `ContinuationStore` — контракт
  read/write/clear без реализации в src (проверено grep) — bind остаётся вне каналов.] Рationale: «в том и смысл localStorage, что он
  восстанавливает прошлый заход; memory не переносится между перезапусками». Следствия:
  `adapter-local.getInitial` НЕ трогаем; «ссылка мертва в local/none» — объявленная
  семантика, не дыра; no-JS GET-форма осмысленна только там, где хранилищем является
  адрес (демо и работает через серверный url-инстанс); правка инициализации инпута
  поиска `bf31d56` согласована (инпут берёт состояние хранилища, а не адрес).
  Моя прежняя реконструкция прецедента modals была неверной и решение её опровергает:
  `everWrote` в modals защищает НЕ приоритет адреса, а семантику носителя — durable
  (localStorage) зеркало переживает F5 ровно чтобы восстановить прошлый заход, memory
  до записи пуст (никакого воскресания), а адрес сеет только addressable-слой, у
  которого адрес и есть носитель (urlStorage.read = decodeChain(адреса)). Кросс-сидинга
  адрес→стор нет ни в одной ветке. Ниже — протокол развилки на дату решения.] Факт кода: `createLocalAdapter` в `getInitial` читает ТОЛЬКО
  хранилище (`adapter-local.ts:21-30`), адрес не видит ни при каком сторе; чистое
  local-приложение без JS фильтров/поиска НЕ имеет (GET-форма пишет адрес в никуда);
  ссылка из url-режима адресату с local-хранением не восстанавливается; каноническая
  чистка адреса живёт в url-адаптере. Стартовые прецеденты: `lib/modals/storages.ts`
  объявляет свойства на интерфейсе: `addressable` («цепочка видна в адресе → можно
  передать ссылкой») + `durable` (переживает reload): url = оба, local = durable без
  addressable, memory = ни того ни другого — т.е. «нет ссылок» — объявленное
  свойство стратегии, а не дыра; `lib/paginate` такой системы флагов НЕ имеет (url-адаптер =
  единственный адресный канал, demo обходит двойным инстансом). Варианты решения:
  (a) задокументировать «не-url хранилище = нет переносимых ссылок»;
  (b) `seed: 'url-first'` в конфиг адаптера: getInitial = адрес поверх стора по
  объявленным ключам, persist — как выбрано (модель демо на стероидах);
  (c) флаги addressable/durable у адаптеров пагинатора (порт vocabulary modals) +
  предупреждение при несогласованности (app ждёт deep-link, а хранилище не addressable).
  Смотрено на решении (2026-10-08): `modals/build.ts:118,123,175-186,272-278`,
  `router/sveltekit.ts` (адрес = единственный носитель,.goto/replaceState),
  `search/core.ts:34-44` (адрес сеет СЕРВЕРНЫЙ рендер данными, клиент перезапрашивает —
  не сидит стор), `form/continuation.ts:2-4` (форма о носителе не знает).
