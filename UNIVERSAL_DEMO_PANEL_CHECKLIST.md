## Решения оператора (зафиксировано 2026-10-08, ask_user)

1. **§4.1 механика отказа — (A) чисто.** `lib/links` собирает по валидатору-замыканию на
   каждое блокируемое поле и вплетает в компилированное `FormDescription` (один узел
   зависимости — компилятор фильтров). Ядро (`bind`/`submit`/адаптеры) НЕ трогать:
   `ValidatorRef` уже принимает функцию (`validators.ts:35,52`), `FieldContext.values` —
   весь набор (`validate.ts:83`), ошибка адресуются через `issue.path ?? f.name`
   (`validate.ts:82`), живой `recheck` уже раскладывает по `path` (`bind.svelte.ts:208,213`).
   Прокидка `formValidator` в bind — НЕ делать; если появится правило без владельца —
   отдельным решением.
2. **Правило `search-with-latest` (q) остаётся вне формы в обоих мирах**: JS — гашение
   поля поиска + плашка с причиной (теперь из `lib/links`); no-JS — deny-safe источника
   (`q` не доезжает до API, `dropped`). Форма фильтров про `q` ничего не знает.
3. **§4.2 URL-привязка — отложена до этапа 4** (отдельная привязка рядом с `bind` vs режим
   в `bind`); к этому моменту решить вопросом по готовому слою `lib/links`.
4. **§7 «Осталось» 12–15 — приняты формулировки документа**: пофайловый `validateForm` по
   компилированному `definition`; `compileDemoPanelSchema` (`SettingsField[]` →
   `FormDescription`, `divider` → группы, `parse` → коммит-маппер); панель бережёт
   `cols` при `layout=list`; `lib/links` — отдельная библиотека со слоями
   core/catalog/panel/svelte (§6.5).

## Модель (из §3 промта — менять только по слову оператора)

disabled ≠ скрыто; причина в helper (отдельного узла нет; `helpProps()` отдаёт id при
`help` ИЛИ `reason`); значения выключенных полей не стираются и возвращаются со снятием
блокирующего; при JS-отправке набор собирает `lib/links` без значений выключенных полей
(дроп переезжает из патча `catalogFilterExtraPatch` в сборщик набора); валидатору отказы не
«добавляют» — он судит всем набором; без JS динамики нет; составитель текста один на helper
и ошибку; одинаковое значение в and/not гасит ЗНАЧЕНИЕ, выбор сохраняется, автоснятия нет;
живой режим (select: change; число: change/blur; текст: по завершению) без кнопки после
гидратации, до — нативная GET с кнопкой; невалидная комбинация не создаётся вовсе
(контрольная точка — создание комбинации: адрес + запрос источника, не запись в store);
адресную строку не переписывать (редиректы отклонены); невалидные входящие из URL не
«лечатся» — объяснение + deny-safe источника.

## Факты по коду (сверено на `b1f4dd2`)

- `view.ts:164-166` `optionsOf` теряет `disabled` (карта только `{value,label}`); состояние
  полей панели уже несёт `disabled/reason/suppressedBy` (строки 124-247) — переезжает в
  `lib/links`.
- Компилятор фильтров `catalog-filter.ts:285-293`: `options` → значения allowlist; нужно

  `contradictoryModeViolations` — владелец = поле.

  есть, в `bind` не прокинут (решение: и не надо).
- `bind.svelte.ts:460`: `field: (name) => viewOf(...)` уже существует (документ §2.3.2 «нет
  доступа по ключу» — устарел частично: геттер есть, нет контракта обвязки и DEV-проверок).
- `PaginatorSettings.svelte`: `fieldState()` есть (удаляется на этапе 6), `jsOnly`/`requires` есть.

## Бюджет веса (жёсткое: «глобальные лимиты не поднимать»)

- Глобально: immutable-gzip 203 KiB, JS 190 KiB — **база на пределе**: замеры на `15d4355`
  дают JS 194564±4 байта против лимита 194560 (красный/дрогжащий гейт — предыстория
  upstream, не наш); в промте заявлено ~9 байт воздуха. Каждый этап — `npm run test:size`.
  Рост клиентской части (`lib/links` в живом коде панелей) платит байтами; серверная часть
  бесплатна.
- Маршруты: `/form` 149.4/150.0 (≈0.6 KiB воздуха!) — перенос панели `/form` может
  потребовать сокращений в самой странице; `/paginator` 121.7/126, `/modals` 128.0/135,
  `/` 123.1/130.
- Практика: любые правки клиентского кода — сразу сравнивать test:size с базовым прогоном
  (замер дребезга — 2 чистых сборки подряд).
